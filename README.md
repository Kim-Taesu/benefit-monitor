# benefit-monitor

공식 공개 출처에서 생활 혜택 후보를 수집하고, 검증 자료를 비교하여 지역별 브리핑을 생성합니다.
Python 3.11 이상과 표준 라이브러리를 사용하며 외부 런타임 의존성은 없습니다.
빌드에는 pyproject.toml에 선언된 setuptools>=68을 사용합니다.

## 실행

프로젝트 루트에서 실행합니다.

```sh
python -m unittest discover -s tests -v
python -m benefit_monitor.cli
python -m benefit_monitor.cli --online
python -m benefit_monitor.briefing
```

기본 실행은 로컬 자료만 처리합니다. --online은 sources.yaml의 공식 공개 HTTPS 출처를 수집합니다.
자동 수집 결과는 검증 전 후보입니다. 공식 근거를 확인한 JSON 배열은 다음 명령으로 가져옵니다.

```sh
python -m benefit_monitor.cli --import-items inputs/verified.json
```

입력 형식은 schema/benefit.schema.json 및 benefit_monitor/models.py를 참고하세요.
공식 근거, 실제 확인 시각, 적용 기간, 대상, 이용료와 조건을 기록해야 합니다.
검증 근거 없는 자료나 미래 확인 시각, 허용 호스트 밖 URL은 거부합니다.
개인 자격·잔여석·쿠폰 재고·예산은 별도로 확인해야 합니다.

## 설정과 처리

sources.yaml은 JSON 문법의 YAML 1.2 파일입니다. 공개 공식 출처, 정확한 호스트 허용 목록,
검증 유효기간 및 요청 상한을 정의합니다. districts.json에는 서울 25개 구가 들어 있습니다.
자치구 수집은 서울시 우리동네 뉴스의 구별 첫 페이지를 대상으로 하며 구청 공지 전체 수집이 아닙니다.
피드가 없는 출처는 자동 수집되지 않을 수 있습니다. 미확인 출처는 보고서의 확인 작업으로 남습니다.

```text
공식 출처 → 후보 수집 → 근거 검증 → 캐시 저장 → 차이 분석
                                              ↓
                                         report.json
                                              ↓
                               briefing.md / briefing.json
```

보고서는 신규·변경·유효·예정·마감 임박·재확인·종료·제외 항목을 구분합니다.
브리핑 생성은 로컬 보고서의 검증 유효기간과 기한을 다시 검사하며 네트워크를 사용하지 않습니다.
서울시(구 미지정 안내), 강서구, 은평구, 나머지 확인된 구 순서로 표시합니다.
구 표시는 이용 자격을 보장하지 않습니다. 여러 구의 안내는 각 구에 표시합니다.
혜택 이용료로 대상을 제한하지 않으며 유료 할인·환급·적립도 포함할 수 있습니다.

## 비용과 접근 원칙

추가 유료 API·LLM API·호스팅·스케줄러를 사용하지 않으며 자원이나 예약 작업을 생성하지 않습니다.
기존 실행 환경 및 계정의 요금과 사용 한도는 별도입니다. 구매·예약·혜택 신청을 실행하지 않습니다.
robots.txt, TLS, 정확한 공식 호스트 허용 목록을 적용하며 접근 제한을 우회하지 않습니다.
HTTP 요청은 기본 60회, 최대 100회이며 재시도와 리다이렉트를 포함합니다.
응답은 최대 2MiB, 타임아웃 15초이며 502 또는 직접 타임아웃은 한 번만 재시도합니다.
자치구 수집은 정상 결과 6시간 캐시와 오류 후 대기시간을 적용합니다.

### 공개 검증 항목

`public/verified.json`에는 공식 원문을 확인한 공개 승인 항목을 관리합니다. 2026-10-27 기준 서울·성남·전국·마트 공개 검증 항목 9건을 등록했습니다. 날짜가 지나면 자동 제외되므로 고정 건수를 보장하지 않습니다. 자동 수집 후보를 검증 완료로 승격하지 않습니다.
공식 원문을 실제로 확인한 공개 정보만 Benefit 스키마대로 작성하고 `public_release: true`를 추가합니다.
공개할 모든 필드와 Git 이력을 사람이 확인해야 합니다. 생년월일·집주소·개인 자격·비밀키는 넣지 마세요.
이 파일은 소스 코드와 함께 보관되므로 `evidence`와 `review_notes`도 공개 가능한 내용만 작성해야 합니다.
자동 개인정보 패턴 검사는 보조 장치이며 모든 개인정보를 식별한다는 보장은 없습니다.

```sh
python -m benefit_monitor.publish --prepare-import
python -m benefit_monitor.cli --online --import-items inputs/public.json
python -m benefit_monitor.publish
```

마지막 명령은 오늘 2시간 이내 온라인 수집 보고서를 요구합니다. 공개 승인 입력과 보고서 내용이
일치하고 기존 검증·기간·needs_recheck·종료·제외 검사를 통과한 항목만 내보냅니다.
확인 시각·요금·최소 지출 등 조건은 유지합니다. `evidence`, `review_notes`, 개인 프로필과
검증 대기 후보 본문은 출력하지 않습니다. 공개 JSON·Markdown·HTML만 `delivery/public/`에 생성합니다.

현재 코드는 서울시 뉴스·25개 자치구 뉴스 목록·정부 정책뉴스·이마트 공식 뉴스·CU 공식 제휴 안내에서 후보를 수집합니다.
강서구·은평구는 서울시 자치구 뉴스 수집 결과를 공유하며 중복 후보나 추가 HTTP 요청을 만들지 않습니다.
구청 사이트의 robots 제한을 우회하지 않으며 구청 전체 공지를 수집한다는 뜻이 아닙니다.
마트는 신세계그룹 뉴스룸의 이마트 행사 공지, 편의점은 CU 제휴 멤버십 안내 범위입니다.
홈플러스 전단·다른 편의점·앱 전용 재고는 자동 수집되지 않습니다.
성남 공식 RSS는 연결했지만 현재 TLS 연결 실패가 관찰돼 성공으로 표시하지 않습니다.
공개 승인 입력을 유지·갱신하는
검증 작업이 별도로 필요합니다. 빈 입력에서는 '공개 승인된 검증 항목 없음' 상태를 표시하며
'혜택 없음'이나 '전체 수집 완료'로 표현하지 않습니다. 검증 입력은 유효기간이 지나면 표시되지 않습니다.

### 배포와 확인

추가 비용 없는 공개 운영이 승인된 뒤, GitHub Settings → Pages → Source를 GitHub Actions로 설정하고
Actions에서 Daily benefit briefing을 수동 실행합니다. 배포 작업이 반환하는 실제 주소를 확인하세요.
예상 주소를 실제 배포 주소로 간주하지 마세요. 표준 Ubuntu runner만 쓰며 외부 API 키는 필요하지 않습니다.
배포용 artifact는 공개 출력 폴더만 포함하며 1일 보관합니다. 캐시·보고서·수집 원문은 업로드하지 않습니다.

표준 공개 runner와 별개로 artifact 저장 공간은 계정 전체 허용량과 과금 설정의 영향을 받습니다.
다른 저장소가 무료 저장량을 소진했을 가능성을 추정하지 않습니다. 계정의 Actions 저장 공간에 대해
추가 지출 0 및 한도 도달 시 차단이 실제 적용되는 것을 확인한 뒤에만 저장소 Actions 변수
`BENEFIT_PAGES_ZERO_SPEND=confirmed`를 설정하세요. 기본값에서는 실행하지 않습니다.
이 변수는 과금 차단 자체를 설정하지 않으며, 과금 설정을 확인했다는 운영 기록일 뿐입니다.
이 프로젝트는 결제정보 등록·유료 한도 확대·계정 과금 설정 변경을 하지 않습니다.

Mac에서 Python의 인증서 경로가 비어 TLS 오류가 발생하는 경우, 시스템 신뢰 인증서를 사용하는
`SSL_CERT_FILE=/etc/ssl/cert.pem python3 -m benefit_monitor.cli --online`로 실행할 수 있습니다.
TLS 검증을 끄지 마세요. 이 경로를 GitHub Ubuntu runner에 강제로 지정하지 않습니다.

수집이나 공개 내보내기가 실패하면 `collection_failed` 상태 페이지만 배포하고 실행은 실패로 표시합니다.
실행 자체가 지연·누락되거나 배포도 실패하면 이전 사이트가 남을 수 있습니다. 화면은 표시 기한이 지나면
기존 추천을 숨깁니다. JSON 소비자는 `status`, `generated_at`, `source_report_at`, `valid_through`와
각 항목의 검증 시각·요금·기한을 반드시 확인해야 합니다. HTML의 안전 숨김은 JavaScript가 필요합니다.

기존 ChatGPT 08:00 예약은 실제 최신 JSON 읽기가 확인된 뒤에만 수정합니다. 실패·날짜 불일치·기한 경과는
'오늘 갱신 실패 또는 연결 미완료'로 전달하며 이전 데이터를 신규 혜택으로 재사용하지 않습니다.
Pages 배포 성공은 ChatGPT 앱 알림 도달을 증명하지 않습니다.

### 예약 실행 환경의 DNS 제한에 대한 보조 읽기 경로

일부 ChatGPT 예약 실행 환경에서는 github.io 주소를 DNS 오류로 읽지 못할 수 있습니다.
동일 저장소의 `briefing-data` 브랜치 `briefing.json`을 GitHub 공식 파일 읽기 기능으로 읽는
보조 경로를 제공합니다. Actions는 Pages에 배포하는 공개 JSON만 해당 파일에 그대로 복사합니다.
보고서·프로필·수집 원문은 복사하지 않습니다. 새 서비스나 별도 키를 만들지 않으며, Actions의
단기 GITHUB_TOKEN을 복사 단계에서만 gh CLI에 전달합니다. 브랜치와 최초 파일은 운영 설정 시 준비합니다.
수집 코드나 공식 출처 요청에는 이 토큰을 전달하지 않습니다. 데이터 브랜치의 push는 수집 작업을 재실행하지 않습니다.
보조 파일도 동일한 생성·수집·검증 시각과 만료 조건 검사를 통과해야 합니다.


운영 주소: https://kim-taesu.github.io/benefit-monitor/ (배포 성공·현재 데이터는 실행 결과와 JSON으로 확인).
2026-10-27 계정의 Actions 추가 지출 예산 $0 및 Usage blocked를 설정 화면에서 확인하고, 과금 설정 변경 없이 무과금 확인 변수를 등록했습니다.

### 수집 범위와 오류 표시

공개 JSON의 `coverage`와 HTML/Markdown에 25개 지역구 및 분야별 상태를 표시합니다.
`checked`는 목록 수집 성공일 뿐 본문 검증 완료가 아닙니다. `cached`는 6시간 이내 목록 캐시,
`failed`는 연결된 수집기의 실패, `not_connected`는 아직 자동 수집기를 연결하지 않은 출처입니다.
검증 건수가 0인 지역도 숨기지 않으며 혜택이 없다고 해석하지 않습니다.
정부 HTML에서는 제목만 키워드로 분류하고 성남 RSS도 관련 키워드로 후보를 제한합니다.
HTTP 502/503/504와 시간 초과는 요청 예산 안에서 한 번만 재시도합니다.
신규 후보의 기간·조건을 자동 검증하는 범용 AI는 사용하지 않습니다. 공개 승인 목록은 공식 본문 검토가 필요합니다.

핵심 출처별 `collection_scope`는 JSON·Markdown·HTML에 함께 표시합니다.
구별 공개 검증 건수는 같은 공식 기사를 중복 등록하지 않고 해당 지역 태그로 집계합니다.
HTML 수집은 robots.txt 404(파일 없음)만 허용하며 403·서버 오류·TLS 오류는 실패로 처리합니다.
이미지 링크의 제목 속성과 뉴스룸 제목 영역을 읽되, 본문 요약의 단어로 무관한 기사를 채택하지 않습니다.

추가 연결 범위: 서울 공공서비스예약 첫 화면, 서울시 평생학습포털 첫 화면 이벤트,
세븐일레븐 공식 할인·멤버십 카드 탭을 수집합니다. 예약 링크의 화면 상태 파라미터는
제거해 같은 서비스를 중복 생성하지 않습니다. 세븐일레븐의 관찰된 두 카드 탭만
명시적으로 URL로 변환하며 JavaScript를 실행하지 않습니다.
이미지에만 있는 조건 또는 공식 안내 사이의 날짜 충돌은 `needs_recheck`로 보류하며
추천에 포함하지 않습니다. 예약 정원은 잔여석으로 해석하지 않습니다.
성남 TLS, 홈플러스 robots 오류, 구청 공지 robots 제한, KT 접속 및 GS25 데이터 연결은
해결되지 않았습니다. 목록 수집 범위를 전체 서비스·전체 제휴로 표시하지 않습니다.

### 장기 운영 상태와 재검증

- 수집 관측값과 공개 승인값은 별도로 관리합니다. 제목 또는 본문 텍스트의 해시가 바뀌면
  승인값을 다시 가져와도 재검증 보류를 유지합니다. 변경 감지는 사실 검증이 아니며,
  본문을 읽었다는 이유로 `verified_at`을 갱신하지 않습니다.
- 첫 관측은 변경 비교 기준만 만듭니다. 이 시점이 과거 검증 본문과 같았다는 증거는 아닙니다.
  편집한 공개 제목과 원문 제목은 다를 수 있어 서로 직접 비교하지 않습니다.
- 본문 확인은 실행당 최대 5건이며 종료·제외·이미 보류된 항목은 제외합니다.
  이전 확인시각, 마감 순으로 순환하며 전체 HTTP 예산 60회 안에서만 실행합니다.
  텍스트 해시는 이미지의 조건 변경을 감지하지 못하며 페이지 공통 문구 변경도 보류를 일으킬 수 있습니다.
- `review_queue`에는 재검증 사유·항목 ID·발견시각·마감이 기록됩니다. 공식 확인 후 승인 목록의
  내용과 검증시각을 갱신해야 보류를 해제할 수 있습니다. 공개 목록 편집 자체는 자동화하지 않습니다.
- `operational_state`는 기존 briefing-data JSON에 함께 저장·복원합니다. 원문·제목·URL·개인 조건을
  복사하지 않고 식별자·해시·시각·오류 종류만 보관합니다. 검증된 스키마만 복원하고,
  실패 브리핑으로 교체할 때에도 이전 운영 상태는 유지합니다. 새 DB나 외부 서비스는 없습니다.
- 상태 없는 최초 실행은 최초 관측이며 이전과의 비교를 주장하지 않습니다. 90일 넘게 발견되지
  않은 비보류 항목은 상태에서 정리하며, 상태 항목은 최대 5,000개로 제한합니다.
- `source_health`는 마지막 시도·성공 및 연속 실패 횟수를 표시합니다. 오류는 DNS/TLS/timeout/
  HTTP 상태/robots/파싱/요청 예산으로 구분하며 원시 예외 문자열은 공개하지 않습니다.
- `run_id`로 동일 실행의 공개 JSON을 식별합니다. `valid_through`는 파일의 당일 최신성 기한,
  항목별 `display_until`은 종료·접수 마감·검증 유효기간 중 가장 이른 시각입니다.
  소비자는 파일 최신성 검사 후 항목별 기한을 다시 검사해야 합니다.
- HTML은 개별 마감된 카드만 숨깁니다. Markdown은 생성 당시 스냅샷이므로 읽는 시점의
  항목 마감 확인이 필요합니다. 화면/Markdown 시각은 `YYYY.MM.DD HH:mm (KST)`, 날짜는
  `YYYY.MM.DD`로 표시하며 JSON의 시간대 포함 ISO 값은 유지합니다.
- 이마트24는 공식 제휴 서비스만 추가 연결했습니다. 전체 이벤트·상품·앱 잔량 수집을 뜻하지 않습니다.

### 예약 브리핑의 품질 피드백 반영

2026-10-28 점검에서 schedule 이벤트 실행 이력은 0건, workflow는 active, 기본 브랜치는
main으로 확인했습니다. cron `0 22 * * *`는 매일07:00 KST이며 설정을 변경하거나 중복 예약을
만들지 않았습니다. 이력 부재만으로 지연·누락 원인을 확정하지 않습니다.
GitHub는 정각 부하에 따른 지연 및 실행 누락 가능성을 안내합니다:
https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule

2026-10-29부터 공개 JSON의 `run_context`는 워크플로의 단일 cron에서 당일 예정시각을
직접 계산합니다. 현재 예정시각은 06:00 KST이며 수동 갱신 또는 예정시각 이전 스냅샷은
정기 실행 성공의 증거가 아닙니다. 같은 날짜의 JSON만으로 오전 정기 수집을
완료했다고 판단하지 않아야 합니다. 수동 복구 배포를 정기 트리거 복구로 보고하지 않습니다.

수집기는 주로 후보 링크를 발견합니다. Npay 결제 재원 누락은 범용 본문 파서의 자동 추출 결과가
아니라 승인 데이터 작성 시 빠진 조건이었습니다. 해당 항목을 운영주체 원문과 대조해 정정했습니다.
`payment_terms`를 등록하는 항목에는 결제 방식·결제 재원·제외 수단·최소지출·한도·공식 근거 URL을
모두 기록해야 합니다. 모르는 조건은 명시적으로 미확인으로 기재하며 빈 문자열은 허용하지 않습니다.
기존 항목의 빈 payment_terms는 결제 조건의 구조화 검토를 완료했다는 뜻이 아닙니다.
이 필드가 있는 항목의 본문 변경 감지는 결제조건 운영주체 URL을 우선합니다.

출처 실패 시 기존 승인값은 원래 verified_at·항목 기한·7일 검증 유효기간 안에서만 남을 수 있습니다.
수집 실패를 성공으로 바꾸거나 캐시 재사용으로 검증시각을 갱신하지 않습니다.
KT 직접 연결과 CU/이마트24 공식 제휴 페이지에 포함된 KT 혜택은 별개 범위입니다.
