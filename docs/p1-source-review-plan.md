# 운영 확인·승인 데이터 재검증·서울 기사 본문 파서

- Pages와 briefing-data의 생성 시각·상태·항목·실행 ID를 비교하고 마지막 실제 배포 커밋을 확인한다.
  push 성공을 배포 성공으로 표현하지 않는다. 현재 커넥터는 workflow_dispatch를 지원하지 않는다.
- 마감 임박·금전 혜택을 우선하여 공식 원문을 다시 읽는다. 실제 확인한 항목만 확인 시각을 갱신한다.
  원문 접근 불가·robots 거부는 검증 성공이 아니며, 기존 조건 충돌은 재검증 보류한다.
- 실제 서울시 기사 표본에서 main/article 태그가 없고 div.news_detail_cont 본문이 하나임을 확인했다.
  mediahub.seoul.go.kr/archives/숫자 URL에서만 이 영역을 선택한다. 유일하고 닫힌 영역만 사용하고,
  모호하면 문서 전체로 대체한다. 다른 URL은 기존 main/article/document 정책을 유지한다.
- 숫자·금액·자격 문구는 삭제하지 않는다. 해시 v4 전환은 같은 응답을 v3(또는 v2) 방식으로도
  비교해 알려진 변경을 보류한다. 새 범위 첫 기준은 baseline이며 자동 사실 검증이 아니다.
- 새 비교 영역 enum만 운영 메타데이터에 허용한다. 본문/URL을 미러로 복사하지 않는다.
- 표준 라이브러리·예산·robots·TLS·허용 호스트·캐시·실패 대기시간·확인 상한을 유지한다.
- LLM API는 정책 변경 검토 문서만 작성한다. 키 발급·키 조회·외부 API 호출·결제 설정은 하지 않는다.

합성 HTML 경계 테스트와 v3/v2 전환 회귀, 전체 Python, 프런트 단위·빌드·브라우저 검사로 검증한다.
원문 전체는 무시된 로컬 검토 폴더에만 두고 코드·공개 문서에는 요약과 공식 링크만 기록한다.
