# 장보기 "이거 싼 건가?" 빠른 확인 — 설계

작성 2026-11-10. 상태: 사용자 승인 대기.

## 의도

사용자 피드백: 장보기 탭에서 자주 사는 품목의 최근 1년 가격과 평균가를 보여주는 점이 "인어교주해적단처럼 시세를 알 수 있어서 좋았다".

이 기능을 쓰는 순간(사용자 설명): 마트나 정육점에서 가격표를 보며 "이게 과연 싼 건가?" 고민할 때다. 대부분 휴대폰으로 본다. 품목명 일부만 쳐도("삼겹") 결과가 나오고, 결과는 짧아야 한다. 오늘 평균가를 크게 보여주고, 그 아래 "기간 평균보다 몇 % 싸다/비싸다"를 붙인다.

차별화(조사 결과, 사용자 동의): 인어교주해적단은 수산물만, KAMIS는 공급자 화면, 폴센트는 온라인 공산품만 다룬다. 우리는 **품목군을 가로지르는 자주 사는 장바구니 하나**와 **기간 평균 대비 판정**을 모바일에서 한눈에 보여준다. 할인행사 연결은 다음 단계에서 다룬다.

## 목표

1. 장보기 탭 검색에서 자주 사는 품목을 부분 입력과 별칭으로 찾으면, 맨 위에 **결과 카드 A안**을 보여준다.
   - 품목명과 출처 한 줄: "돼지 삼겹살 · 전국 평균 소매가"
   - 오늘 평균가를 크게 쓰고 공식 단위를 붙인다: "2,650원 /100g"
   - 판정 배지: "▼ 12개월 평균보다 8% 쌈"처럼 항상 정확한 %를 쓰고, 색은 ±10% 기준을 따른다(아래 "사용자 결정 1")
   - 작은 글씨로 기준값과 조사일: "12개월 평균 2,880원 · 11/7 조사"
   - 같은 부류의 다른 장바구니 품목을 링크로 둔다: "목살 · 앞다리 ›"
2. 기준은 **있는 기간만큼의 평균**이다. 최대 12개월이고, 1년치가 없으면 기간을 줄인다. 배지에는 실제 기간을 쓴다("4개월 평균보다"). 이 규칙은 모든 품목에 똑같이 적용한다(사용자 결정).
3. 고기는 축산물품질평가원이 2026-07-01에 조사 방법을 바꿨다. 그래서 변경 이후 기간 평균만 쓴다(사용자 결정: "조사 방식 변경 후 N개월 평균").

## 하지 않는 것

- 할인행사(수산대전·농할 등) 연결. 다음 단계로 미룬다.
- 알림, 지역별 비교, 그래프, 가격 직접 입력 화면 신설. 기존 `GroceryCalc` 매장가 계산기는 그대로 둔다.
- AI 문구. 이 카드는 숫자 계산만 한다.
- 유료 API, 인증키 API(KAMIS Open API, data.go.kr 등), 검색 로그 수집 서비스.

## 실패로 보는 경우 (반목표)

- 데이터가 없거나 기간이 짧은데 "12개월 평균"이라고 쓰는 것. 기간을 부풀리거나 값을 추정해 채우는 것.
- 단위를 임의로 환산해서 공식값과 다른 숫자를 크게 보여주는 것.
- 휴대폰 화면에서 결과 카드가 첫 화면에 보이지 않는 것.

## 제약 (AGENTS.md)

- Python 표준 라이브러리, 익명 공개 HTTPS 페이지만 사용한다. robots를 지키고, 출처 allowlist(`www.kamis.or.kr`, `www.ekapepia.com`)는 그대로 둔다.
- HTTP 요청 예산은 실행당 최대 100회, 기본 60회다. 기존 장보기 수집과 다른 출처 수집이 이미 예산을 쓰고 있다(#37에서 예산 소진으로 부위가 빠진 적이 있다).
- 공식 게시값을 그대로 옮기고, 사람 검증 전 값이라는 안내를 유지한다. 장보기 시세는 혜택 목록·검토 큐·AI 조사에 섞지 않는 별도 표시 채널이다(2026-11-09 승인).
- 로직을 바꾸면 `python -m unittest discover -s tests -v`를 실행한다. 프런트는 기존 vitest와 Playwright e2e를 실행한다(e2e는 시스템 Chrome, 임시 config 필요).

## 데이터 출처 (2026-11-10 정찰로 확인, 요청 8회)

### KAMIS (농·수산·가공)
- `https://www.kamis.or.kr/customer/price/agricultureRetail/period.do?action=monthly&productclscode=01&itemcategorycode=<부류>&itemcode=<품목>&kindcode=<품종>&productrankcode=<등급>&yyyy=<연도>&period=3&convert_kg_yn=N`
- 익명으로 200 응답이 오고 0.25초가 걸린다. robots.txt는 Googlebot의 검색 경로만 막는다.
- 응답 표의 형태: 헤더 `['구분','2026년','2025년','2024년','2023년','평년']`, 행 `01월`…`12월`. 확인한 행은 13행 이상이고, 쌀(100/111/EE/0)로 확인했다.
- 최근 12개월 평균은 아직 조사가 없는 달과 진행 중인 이번 달을 빼고, 마지막 12개 완료 월(올해와 작년 열을 이어 붙임)의 월평균을 단순 평균한다. 빈 칸('-')은 그 달을 빼고 기간을 줄인다.
- 일별 1년 범위 조회(`action=daily` + startday/endday)는 90초 안에 응답이 없었다. **사용하지 않는다.**
- 표 하단의 정확한 행 구성과 `period` 파라미터의 의미는 구현할 때 실제 응답 fixture로 확정한다.

### 축산물품질평가원 (고기·계란)
- 지금 쓰는 `regionAvgPrice.do`에 `searchStartDate=2026-07-01&searchEndDate=<최근 조사일>`를 넣으면 행 하나(지역별)가 돌아온다. 서울 삼겹살 2,956원으로, 11/8 하루 값 2,866원과 달랐다. 그래서 **기간 평균으로 추정한다.**
- 구현할 때는 먼저 하루치 값 몇 개와 대조하는 검증을 한다. 기간 평균이 아니라면(예: 마지막 날 값) 이 방식은 버리고 고기 배지를 숨긴다. 일별 값을 쌓아 평균을 만드는 방식은 요청 수가 크므로 사용자에게 다시 묻는다.
- 시작일은 2026-07-01로 고정한다. 그 이후 12개월이 쌓이면 최근 12개월로 굴린다.
- robots.txt: `User-agent: *`에 대해 `/v3/hereMeat`는 허용된다.

## 장바구니 목록 (사용자 승인, 25개)

| 묶음 | 품목 |
|---|---|
| 고기·알 (7) | 삼겹살, 목심, 앞다리, 한우 등심 1등급, 미국산 갈비살, 닭(육계), 계란 30구 |
| 채소 (12) | 배추, 무, 양파, 대파, 감자, 당근, 오이, 애호박, 상추, 시금치, 콩나물, 깐마늘 |
| 기타 (6) | 쌀, 두부, 사과, 바나나, 고등어, 오징어 |

- 목록은 `sources/groceries.json`(groceries 출처 설정 원본)에 둔다. 항목마다 공식 품목·품종·등급 코드와 **별칭**을 넣는다(예: 계란→"계란, 달걀", 파→"대파, 파", 애호박→KAMIS "호박"의 해당 품종, 오징어→"물오징어").
- KAMIS 품목·품종 코드는 이미 수집 중인 일간 페이지의 행과 연결한다. 정확한 kindcode와 등급 매핑은 빌더가 일간 페이지 fixture로 확정한다.
- 늘리는 방식(사용자 결정): 처음에는 이 목록만 두고, 검색이 자주 안 걸리면 조금씩 늘린다. 정적 사이트라 실패한 검색을 자동으로 모으지 않는다. 피드백으로 판단한다.
- 돼지 뒷다리와 닭 부위별 가격은 공식 소매가가 없어서 넣지 않는다.

## 화면

- 기존 `GrocerySection.vue`의 "품목 찾기" 검색창(`#grocery-q`)을 그대로 쓴다. 검색어가 장바구니 품목명이나 별칭과 부분 일치하면, 결과 목록 위에 결과 카드 1장을 보여준다. 여러 개가 맞으면 가장 잘 맞는 것을 고른다(정확 일치 → 접두 일치 → 부분 일치 순). 나머지는 카드 하단 링크로 보여준다.
- 장바구니에 없는 검색어는 지금처럼 전체 시세 목록을 필터링한다. 결과가 0개면 기존 빈 화면에 "아직 자주 사는 품목에 없어요" 안내를 더한다.
- 360~390px 폭에서 검색창 바로 아래 첫 화면 안에 카드가 보여야 한다. "이번 주 장보기 추천"이 검색창보다 위에 있으므로, 검색어가 있을 때 결과 카드가 추천보다 먼저 보이게 배치를 조정한다. 방법은 빌더가 정한다.
- 판정 배지 규칙: 오늘값 ÷ 기간 평균 − 1을 반올림한 %로 판정한다. 색 기준은 아래 "사용자 결정 1"을 따른다. 기준 기간이 1개월 미만이면 배지를 숨긴다.
- 기간 평균이 없거나, 파싱에 실패했거나, 오늘값과 단위가 다르면 배지를 숨기고 가격만 보여준다.

## 수집과 캐시

- 오늘 가격은 지금처럼 매일 수집한다(KAMIS 일간 페이지, 축산 지역 평균).
- 기간 평균은 품목당 요청 1회로, 주 1회 별도 무료 수집 실행에서 받는다(아래 "사용자 결정 2").
- 실패한 품목은 기존 실패 쿨다운 규칙을 따르고, 마지막으로 성공한 평균을 기간 표기와 함께 유지한다. 값이 30일을 넘으면 버리고 배지를 숨긴다.
- 공개 산출물은 별도 `baselines`로 낸다. 품목 id마다 `{avg, months, from, to, source}`를 담는다. 기존 grocery 묶음의 스키마는 바꾸지 않는다(아래 "빌더 점검 후 정한 것").

## 빌더에게 맡기는 것

- 파서 구현, fixture 구성, 캐시 파일 위치와 형식
- 결과 카드 컴포넌트를 분리할지, 스타일 세부(A안 목업: `.superpowers/brainstorm/…/search-result.html`의 A카드)
- 별칭 매칭 세부(공백, 대소문자, 초성 검색은 하지 않음)

## 빌더 점검 후 정한 것 (작성자 판단, 사용자 검토 대상)

- **기준값 저장 위치:** 기존 grocery 묶음(`schema_version` 1, AI 입력 검증 `claude_trial.validate_host` kind `grocery`가 다시 만들어 대조함)은 건드리지 않는다. 기준값은 별도 산출물 `baselines`(자체 schema_version)로 내고, 프런트가 품목 id로 붙인다. 그래서 유료 AI 경로의 입력과 검증은 바뀌지 않는다. `publish.py`·`public_snapshot.py`를 고치면 기존 규칙대로 `policy_sha256`을 다시 기록한다.
- **고기·계란 행 매핑:** 수집 중인 행을 그대로 쓴다. 한우 등심 → "등심 1등급", 미국산 갈비살 → "갈비살(냉장) 미국산", 계란 30구 → "XL30구 일반란". 오늘값과 기간 평균은 반드시 같은 (species, part, 등급) 행에서 나와야 하고, 다르면 배지를 숨긴다.
- **카드 하단 링크:** 같은 장바구니 묶음(고기·알 / 채소 / 기타)의 다른 품목을 최대 3개 보여준다. 검색어에 함께 걸린 다른 장바구니 품목이 있으면 그것을 먼저 보여준다.
- **예산 수치 정정:** 실제 실행당 상한은 `sources/_config.json` 기준 95회다. AGENTS.md에는 장보기를 약 17~21회로 적어 두었다.

## 사용자 결정 (2026-11-10, "추천대로")

1. **배지 기준선:** 결과 카드는 % 숫자를 항상 정확히 쓴다("12개월 평균보다 8% 쌈", "…와 같음"). 색은 기존과 같은 ±10% 기준을 따른다. −10% 이하는 초록(cheap), +10% 이상은 빨강(pricey), 그 사이는 회색(normal)이다. 기존 목록 배지, 이번 주 추천, "평년보다 싼 것만" 필터, `grocery_pick` AI 검증은 바꾸지 않는다. 앞의 "평소 수준 ±3%" 안은 폐기한다.
2. **수집 일정과 보존:** 기간 평균은 일일 수집에 섞지 않는다. **주 1회 기간 평균만 받는 무료 수집 실행**을 따로 둔다(GitHub Actions, 유료 호출 없음, 요청 약 25회, 그 실행 자체 예산 안에서). 결과는 기존 `briefing-data` 브랜치에 기준값 파일 하나로 저장하고, 일일 공개 빌드가 그 파일을 읽어 `baselines`를 낸다. 실패한 품목은 직전 값을 기간 표기와 함께 유지한다. 30일이 지나면 버리고 배지를 숨긴다. 위 "수집과 캐시" 절의 '실행당 8회, 7일 캐시'는 이 결정으로 대체한다.
3. 이 결정에 맞춰 AGENTS.md의 장보기 수집 설명(요청 수, 실행 일정, briefing-data 저장 파일)을 갱신한다. 이는 구현 작업에 포함된다.
