# AI 교차 조사와 기준 충족 시 자동 공개 — 설계

작성: 2026-11-07. 사용자 결정은 "사용자 결정"으로, 설계자 판단은 "설계 판단"으로 표시한다.

## 왜 하는가

사용자가 AI agent에 기대하는 일은 두 가지다.
1. 수집기가 가져온 정보의 품질을 높인다(조건·기간·비용을 원문 근거로 정리).
2. 한 번 더 조사해서 신뢰도를 높인다.

2026-11-07 점검 결과 둘 다 거의 일어나지 않는다.
- AI는 후보의 공식 원문 1건만 받는다. 웹 검색 도구가 없고, 다른 출처와 대조하지 않는다.
- 하루 2건만 조사한다. 형식 검사 통과율은 21건 중 3건(14%)이다.
- 통과한 결과도 비공개 검토 대기열에만 쌓인다. 공개 96건 중 AI 결과가 반영된 항목은 0건이다. `public/verified.json`은 11/4 이후 갱신이 없다.

사용자 결정: 방향 A(공식 출처 교차 조사)와 C(기준 충족 시 자동 공개). 유료 웹 검색(B)은 이번 범위가 아니다.

승인 문구 (2026-11-07, AGENTS.md 새 절에 그대로 인용):
- "A,C 로 하고 C 는 기준 충족하면 자동공개해"
- 가장 피할 실패: "과거 자료나 끝난 이벤트인데 현재 운영중인, 실제로 앞으로 오픈할것처럼 보이는거가 가장 용납하기 어렵지"
- 상시 운영 혜택: "다른 증거가 있으면 공개해도 돼"
- 비용: "금액은 난 월 $10~20 도 괜찮은거같음"
- 어드민: "그 자리에서 바로 내릴 수 있는 방법. 어드민 페이지를 하나 만들어서 운영하면 될듯", 반영 지연은 "조금 걸려도 됨"
- 이 설계 문서 자체에 대한 승인은 구현 전에 따로 받는다.

## 가장 피해야 할 실패 (사용자 결정)

**끝났거나 지난 자료가 지금 진행 중이거나 앞으로 열릴 것처럼 보이는 것.** 사용자 표현으로는 "배반감·배신감". 틀린 금액보다 이게 더 나쁘다. 그래서 자동 공개 기준의 중심은 "지금 유효하다는 증거"다. 기준이 애매하면 공개하지 않는 쪽(보류)을 고른다.

## 목표

- 조사할 후보마다 관련 공식 페이지를 더 모아, AI가 여러 원문을 대조해 정리한다.
- 아래 기준을 모두 넘는 결과는 사람 승인 없이 사이트에 공개한다.
- 공개된 항목은 매일 다시 확인한다. 원문이 바뀌거나 사라지거나 종료되면 내린다.
- 사용자가 어드민 페이지에서 공개 항목을 바로 내릴 수 있다.
- 비용은 월 $15 상한 안에서 돈다.

## 비목표

- 유료 웹 검색, 뉴스·블로그 크롤링, 다른 LLM 공급자.
- 사람이 승인한 기존 공개 항목(`public/verified.json`)을 AI가 고치거나 내리는 것.
- 축제 섹션(`festivals`)을 AI 조사 대상에 넣는 것.
- 어드민에서 새 항목을 만들거나 내용을 편집하는 것(내리기·되살리기만).

## 반(反)목표: 기술적으로 돌아가도 실패인 경우

- 종료된 행사, 작년 차수, 연도 없는 날짜가 "진행 중"으로 공개됨.
- AI가 계산·추정한 날짜나 금액이 공개됨.
- 자동 공개 항목과 사람 승인 항목이 화면에서 구분되지 않음.
- 사용자가 내린 항목이 다음 실행에서 다시 올라옴.
- 월 상한을 넘어 과금됨.

## 제약

- 무료 인프라 원칙은 그대로다. GitHub Actions(공개 저장소), GitHub Pages, GitHub API 무료 범위만 쓴다. 새 서버·DB·호스팅은 없다.
- 공식 출처는 익명 HTTPS, robots 준수, `sources.yaml`의 도메인 허용 목록만 쓴다. 실행당 HTTP 상한은 100이고, 기본 수집과 합산해 넘지 않는다.
- Python 표준 라이브러리만 쓴다. 모델은 Claude Haiku 5.5 고정이고, 더 비싼 모델로 자동 전환하지 않는다.
- 키와 평문 원장은 공개하지 않는다. 기존 암호화 상태(age)와 비용 예약 원장 방식은 유지한다.
- AGENTS.md에 이번 승인을 새 절로 기록한다. 기존 "AI 새 사실은 비공개 검토 대기에만" 원칙은 이 기준을 통과한 항목에 한해 바뀐다.

## A. 공식 출처 교차 조사

### 추가 문서를 어디서 찾나 (설계 판단)

웹 검색 없이 공식 출처만으로 찾는다. 후보마다 아래 순서로 최대 3개를 더 가져와 원문 포함 최대 4개를 AI에 준다.
1. 후보 원문 본문 안의 링크 중 허용 목록 도메인(`sources.yaml`의 모든 출처 도메인 합집합)에 있는 것. 신청 페이지, 주최 기관 공지, 상세 안내 등이다.
2. 같은 기관의 공식 목록 페이지에서 제목이 크게 겹치는 글. 수집기가 이미 받아 둔 목록 캐시를 쓰며, 추가 요청은 하지 않는다.

- 모든 요청은 robots, 크롤 지연, 실행 HTTP 예산, 리다이렉트 금지(`OfficialReader` 규칙)를 따른다.
- 허용 목록 밖 도메인은 가져오지 않는다. 대신 "확인 못 한 외부 링크"로 기록만 해서 AI와 사람이 볼 수 있게 한다.
- 추가 문서를 하나도 못 찾는 후보도 조사는 한다. 다만 아래 자동 공개 기준의 "교차 확인"은 통과하지 못한다.

### AI가 하는 일

- 지금처럼 필드별 사실을 원문 조각(segment) 근거로 뽑는다. 근거로 여러 문서의 조각을 함께 고를 수 있다.
- 문서끼리 값이 다르면 그 필드는 `disputed`로 두고 양쪽 조각을 근거로 단다.
- 날짜 판단 규칙을 강화한다.
  - 연도가 없는 날짜는 `unknown`으로 두고 이유를 쓴다.
  - 원문 게시일·수정일을 별도 필드로 뽑는다.
  - "지난 차수", "종료", "마감", "결과 발표" 같은 문구가 있으면 그 조각을 근거로 남긴다.
- 출력 스키마가 바뀌면 기존 승인대로 문법 시험 요청이 한 번 나간다.

## C. 자동 공개 기준 (사용자 결정 + 설계 판단)

아래를 **모두** 만족해야 자동 공개한다. 하나라도 빠지면 비공개 검토 대기에 둔다.

1. **형식**: 출력 계약 검사를 통과하고, 모든 근거 인용이 해당 공식 원문 본문에 그대로 있다(기존 검사).
2. **충돌 없음**: `disputed` 필드가 없고, 해결 안 된 충돌도 없다.
3. **핵심 사실 확인**: summary, conditions, fee_status, eligibility가 `supported`다. 비용이나 결제가 있는 혜택은 cost_details나 payment_conditions도 `supported`여야 한다.
4. **현재 유효성** (사용자 결정, 가장 중요): 둘 중 하나.
   - **기간형**: 종료일(행사 종료 또는 신청 마감)이 원문에 연도까지 명시되어 있고 오늘(KST) 이후다. 시작일이 원문에 있으면 그대로 쓰고, 없으면 시작일 미확인으로 둔다.
   - **상시형** (사용자 결정: 다른 증거가 있으면 공개): 종료일은 없지만 세 가지를 모두 만족한다.
     - 원문 게시일 또는 수정일이 최근 90일 이내이고 원문에 명시돼 있다(설계 판단: 90일).
     - 두 곳 이상의 공식 문서가 현재 운영 중임을 근거로 뒷받침한다.
     - 종료·마감·지난 차수 신호가 어느 문서에도 없다.
5. **교차 확인**: 공식 문서 2곳 이상을 실제로 가져왔다. 기간형은 종료일을, 상시형은 운영 사실을 서로 다른 문서 2곳 이상이 뒷받침한다. 같은 기관의 같은 글이 주소만 다르면 1곳으로 센다(본문 해시 기준).
6. **연도 함정 차단**: 게시일이 1년 이상 지났거나, 기간 연도가 오늘 연도·다음 연도가 아니거나, 원문 제목·본문에 지난 연도 차수 표시가 있으면 공개하지 않는다(설계 판단).
   - 기간형에서 게시일이 원문에 없을 때: 종료일이 연도까지 명시되고 오늘 이후이며 두 문서가 같은 종료일을 뒷받침하면 통과한다. 연도 명시 종료일 자체가 현재성의 증거이기 때문이다(설계 판단). 상시형은 게시일·수정일이 필수다.
7. **내림 목록에 없음**: 사용자가 어드민에서 내린 항목은 원문이 바뀌어도 자동으로 다시 올리지 않는다. 원문이 바뀌면 "다시 검토 대기"로만 둔다. 매칭은 후보 ID(출처+URL)와, 정규화한 제목+주최 기관 두 가지로 한다. 같은 행사가 새 주소로 다시 올라와도 막기 위해서다(설계 판단).
8. **최신 확인**: 공개 시점 기준 마지막 원문 확인이 30시간 이내다.

기준 판정은 결정론적인 호스트 코드가 한다. 모델의 판단 문장은 판정에 쓰지 않는다.

### 공개 후 감시

- 재확인은 AI가 아니라 무료 일일 수집(`briefing-pages` workflow)의 본문 확인 단계에서 한다. AI 실행이 실패하거나 원장이 중단돼도 감시는 계속된다(설계 판단). AI 실행도 재조사 때 함께 확인한다.
- 자동 공개 항목의 원래 원문을 매일 다시 읽는다.
  - 본문 해시가 바뀌면 즉시 내리고 재조사 대기에 둔다. 다음 조사에서 다시 기준을 넘으면 재공개한다.
  - 원문이 사라지면(4xx) 즉시 내린다.
  - 종료일이 지나면 내린다(기존 `display_until` 처리와 동일).
- 상시형은 매일 재확인할 때 게시일·수정일 90일 조건도 다시 본다.
- 마지막 원문 확인이 30시간을 넘은 자동 공개 항목은 화면에서 숨긴다. 일반 수집도 AI도 확인하지 못했다는 뜻이다. 반목표(지난 자료 노출)를 우선한다. 숨김은 내림과 다르게 다음 확인이 성공하면 자동으로 돌아온다(설계 판단).

### 화면 표시

- 자동 공개 항목은 기존 혜택 목록에 함께 나온다.
- 카드와 상세 창에 "AI 정리 · 공식 원문 N곳 대조 · 확인 시각"을 표시하고, 상세 창에는 대조한 원문 링크 목록을 둔다.
- 사람 승인 항목과 시각적으로 구분한다.
- 주제 카드 후보에도 들어갈 수 있다. 단어 규칙 주제 후보는 공개 승인 항목과 같은 방식으로 붙는다.

## 어드민 페이지 (사용자 결정)

- **위치**: 같은 Pages 사이트의 `/admin.html`. 메인 화면에서 링크하지 않는다.
- **인증**: 사용자가 만든 GitHub fine-grained 토큰을 넣는다. 권한은 이 저장소만, contents 쓰기와 actions 쓰기다. 토큰은 그 브라우저에만 저장하고 사이트·저장소·로그에 보내지 않는다(GitHub API 호출에만 씀).
- **목록**: 현재 자동 공개 항목과 각 항목의 근거를 보여 준다. 대조한 원문, 기간 근거 문구, 확인 시각, 판정에 쓰인 기준이 나온다.
- **내리기**: 데이터 브랜치(`briefing-data`)의 내림 목록 파일에 후보 ID·시각·메모를 기록하고, 공개 배포 workflow를 다시 실행한다.
  - 반영까지 2~3분 걸려도 된다(사용자 결정).
  - 내림 목록은 모든 공개 경로가 읽는다. 일반 수집 배포, AI 재배포, snapshot 재검사 모두 해당한다.
- **되살리기**: 내림 목록에서 지운다. 다음 실행에서 기준을 다시 통과하면 재공개된다.
- 메인 사이트와 마찬가지로 외부 스크립트·추적 없이 GitHub API만 호출한다.

## 처리량과 비용 (사용자 결정: 월 $10~20 수용)

- **조사 건수**: 하루 최대 20건(설계 판단). 대상은 그날 새로 들어오거나 바뀐 후보, 그리고 원문이 바뀐 자동 공개 항목의 재조사다. 우선순위는 원문 변경으로 내려간 자동 공개 항목, 새 후보, 오래 확인 안 한 후보 순이다.
- **추가 문서와 HTTP**: 후보당 최대 3개. HTTP 상한 100은 workflow 실행 1회 기준이다(AGENTS.md 규칙). AI 실행은 자체 수집(현재 약 44회)을 한 뒤 남는 예산(약 50회)만 조사에 쓴다. 후보 1건당 robots 포함 최대 약 4~5회라 실제로는 하루 10~12건 정도가 된다. 모자라면 다음 날로 넘긴다. 20건은 상한일 뿐 목표가 아니다(설계 판단).
- **하루 요청 상한**: 조사 20, 주제 1, 문법 시험 2로 23회(설계 판단).
- **실행일 수 상한**: 코드의 총 실행일 14일 상한(`MAX_RUN_DAYS`)과 2026-11-19 만료를 없앤다. 하루 1회 실행(이미 끝난 날은 건너뜀)은 유지한다.
- **비용 상한**: 프로그램 원장에 월 $15 상한을 둔다(설계 판단: $10~20의 중간). 달이 바뀌면(KST 기준) 월 사용액만 새로 센다. 누적 기록과 예약 방식은 유지하고, 원장 초기화는 없다. 평생 누적 상한은 두지 않는다. 사용자가 언제든 workflow를 끄면 멈춘다.
- **기존 실험 조건 교체**: 원장의 $5 고정 상한(`CAP`)과 요청 기록 200행 제한을 월 상한 구조로 바꾼다. 기존 36건 기록은 그대로 두고, 11월 사용액에 포함한다.
- **사용자 몫** (사용자 결정, 2026-11-07: "일단 현재 유지하다가 크레딧 다 쓰면 내가 알림받을 때 수동 충전할게"): 지금 남은 선결제(약 $4.92)로 시작한다. 자동 충전이나 미리 충전은 하지 않는다. 크레딧이 떨어지면 사용자가 알림을 받고 직접 충전한다. 프로그램의 월 $15 상한은 그대로 두는 두 번째 안전장치다.
- **크레딧 소진 처리** (설계 판단):
  - Anthropic이 잔액 부족으로 거절하면(과금 없는 4xx), 원장을 중단(halt) 상태로 만들지 않는다. 그날만 "credit_exhausted"로 기록하고 남은 조사는 건너뛴다.
  - 그날 AI workflow를 실패로 표시해 GitHub 실패 알림 메일이 가게 한다. 이것이 사용자가 받는 알림이다. Anthropic 콘솔의 잔액 알림 메일은 프로젝트가 보장하지 않는다.
  - 다음 날 실행은 자동으로 다시 시도한다. 충전 전에는 같은 방식으로 건너뛴다. 사람이 중단을 풀어 줄 필요는 없다.
  - 이미 공개된 자동 항목은 무료 일일 수집의 감시로 유지되고, 원문이 바뀌거나 끝나면 내린다.
  - 어드민 페이지 상단에 "AI 조사 중지: 크레딧 소진(마지막 성공 날짜)"을 표시한다.
- **예상**: 교차 조사 건당 약 $0.01 안팎(오늘 실측 1건 약 $0.002의 3~5배). 하루 20건이면 월 약 $6이고, 주제 카드와 문법 시험까지 합쳐도 $15 안이다. 실측으로 확인한다.

## 공개 경로의 신뢰 구조 (설계 판단, 세부는 빌더 몫)

- 자동 공개 승인 기록은 `briefing-data` 브랜치에 평문으로 둔다. 공개해도 되는 사실과 근거만 담고, 키·원장·비공개 검토 자료는 넣지 않는다.
  - 이 기록은 기존 `public/verified.json`과 별개인 두 번째 승인 목록이다.
  - 신뢰된 Actions runner의 AI 실행만 쓴다.
- 일반 수집 배포와 snapshot 재검사는 이 기록을 읽어 결정론적으로 다시 검사한다. 칸 형식, 허용 도메인, 기간 유효성, 내림 목록, 30시간 신선도를 본다. 통과한 것만 공개한다. 원문 재수집은 하지 않는다.
- 공개 JSON에 항목별 `review` 표시(사람 승인 / AI 자동, 대조 원문 목록, 확인 시각)를 추가한다. 프런트엔드가 이 칸을 검증한다.

## 빌더에게 맡기는 것

- 추가 문서 탐색의 세부 규칙(링크 추출, 제목 유사도 기준, 중복 판정).
- 출력 스키마(wire) 변경 방식과 프롬프트 문구.
- 자동 승인 기록·내림 목록의 파일 형식, 위치 이름, 동시 쓰기 처리.
- 어드민 페이지 화면 구성. 단, 토큰을 브라우저 밖으로 보내지 않을 것.
- 비용 원장의 월 상한 구현.
- 테스트 구성. 기존 Python 단위, 프런트 단위, E2E 체계를 따른다.

## 성공 기준

- 첫 주 안에 자동 공개 항목이 실제로 생긴다. 다만 기준을 낮추는 대신 0건이면 보류 사유 분포를 보고 조정을 제안한다.
- 자동 공개 항목 중 종료·지난 자료가 진행 중처럼 보이는 사례가 0건이다.
- 어드민 내리기 후 3분 안에 사이트에서 사라진다.
- 월 비용이 $15 상한 안이다.
