# 맥락 없는 서브에이전트 실행 평가 — 2026-11-04

## 판정

**실행 준비도: 미달. 보류 처리: 이번 관측 범위에서 적절. 사실 정확도·추가 조사 가치·주제 정밀도: 평가 불가.**

실제 조사 성공으로 보고하지 않는다. 원문 열람이 0건인 이번 결과로 모델 성능이나 문서의 정상 경로를 검증할 수 없다. 이 시험은 API 모델 비교가 아니라 Codex 서브에이전트가 플레이북만으로 작업할 수 있는지 확인한 것이다.

## 시험 방법과 독립성

- 이전 대화를 전달하지 않은 새 서브에이전트(fork_turns=none)를 실행했다.
- docs/ai/README.md를 시작점으로 6개 문서, AGENTS.md, sources.yaml, public/verified.json을 읽게 했다.
- 후보 3개를 에이전트가 직접 선정했다. 메인 세션은 원문 정답이나 추천 주제를 전달하지 않았다.
- 과제는 조사 초안과 유효한 승인 입력에 한한 주제 제안이었다. 외부 LLM API·결제·공개 승인은 하지 않았다.
- 실행 중 로컬 환경이 unavailable로 전환되었다. robots 확인 명령의 실행 결과를 회수하지 못했고 파일 저장도 완료하지 못했다.
- 이후 메인은 GitHub/웹 읽기 도구가 작동한다는 도구 가용성만 전달했다. 서브에이전트의 회수된 최종 결과에는 추가 원문 열람이 없다.
- 메인의 독립 원문 대조는 별도로 수행했고 서브에이전트 실적으로 합산하지 않았다.

## 회수된 결과

| 후보 | 조사 상태 | supported 주장 | 주제 연결 | 적절했던 처리 |
|---|---|---:|---:|---|
| 서울레스토랑위크 Npay 적립 | blocked / tool_failure | 0 | 0 | 저장 종료일 2026-10-29 경과를 확인하고 재공개하지 않음 |
| 청계 A01 야간 버스 | blocked / tool_failure | 0 | 0 | 종료일 없음과 현재 무료 운행을 동일시하지 않음 |
| 서울시민대학 2학기 | blocked / tool_failure | 0 | 0 | 강좌 운영기간과 지금 접수 가능한지를 구분 |

3개 초안 모두 candidate_id=null, sources=[], supported 없음, 사실 제안은 null/unknown이다. 이는 누락을 숨기지 않은 결과이나 출력 계약을 충족하는 성공 객체가 아니다. topics 결과는 빈 배열이다.

실제 HTTP 시도는 0~1회로 미확정이다. 제출 명령은 robots 요청 최대 1회였지만 실행 서버 연결이 끊겨 HTTP 단계까지 갔는지 알 수 없다. 성공 응답은 0건이다. 토큰·사용비용·모델의 정확한 버전도 호스트 계측이 없어 미확정이다. 기존 ChatGPT/Codex 비용이 0원이라고 주장하지 않는다.

## 메인 평가

| 평가 항목 | 판정 | 근거 |
|---|---|---|
| 작업 이해 | 관측 범위 통과 | 구매 적립, 상시 이동, 혼합요금 교육을 구분해 후보 선정 |
| 허위 근거 방지 | 관측 범위 통과 | 미열람 문서의 URL 조회 성공·해시·인용을 만들지 않음 |
| 만료 및 승인 경계 | 관측 범위 통과 | 만료 혜택과 검증 미확인 입력을 주제에 연결하지 않음 |
| 결과 계약 | 미충족 | ID 등 호스트 필수 입력 없이 null 반환 |
| 조사 실행 | 미완료 | 환경 장애로 원문 열람 없음 |
| 주제 분류 | 평가 불가 | 분류 가능한 검증 입력 자체가 제공되지 않음 |
| Python 대비 개선 | 평가 불가 | 추가로 확인한 사실 0건; 조사 수행 기회가 없었음 |

기계적으로 unknown만 반환한 결과를 높은 정확도로 채점하면 안 된다. 단순 성공률이나 점수를 붙이지 않는다.

## 문서와 실행 설계의 문제

### P0: 입력 묶음이 없다
계약은 candidate_id, approved_claims, snapshot_id를 호스트가 제공한다고 하지만 파일 경로·생성 명령·필수 필드 검사·샘플이 없다. verified.json에는 그 ID가 저장되어 있지 않다. 기존 models.Benefit.id 산식은 코드에 존재하지만 플레이북에 연결돼 있지 않다.

수정 방향: 호스트가 만든 research-input.json / topic-input.json 샘플과 생성 절차를 문서화한다. ID를 모델에게 임의 생성하게 하지 않는다. 현재 표시 가능 여부도 프런트엔드/공개 게이트와 같은 규칙으로 호스트에서 계산한다.

### P0: 조사 후 승인, 주제 입력으로 넘어가는 단계가 비어 있다
연구 초안의 claim ID와 기존 승인 목록을 어떻게 결합하는지, 누가 승인하며 어떤 스냅샷으로 다음 작업에 전달하는지가 없다. 이 상태에서 정상적인 에이전트는 주제 작업을 보류하게 된다.

수정 방향: 실제 조사 초안의 무단 승인을 막으면서, 별도로 사람이 승인한 고정 표본으로 주제 작업을 독립 시험한다. 승인 전환 자체는 운영 구현의 별도 단계로 명시한다.

### P0: 현재 모드와 미래 모드가 섞여 있다
README는 API 정책 변경 전 로컬 검토만 허용한다고 쓰면서 공식 페이지 도구의 제안도 담고 있다. 도구 명세만 있고 실제 제공 여부는 없다. 읽기 자체가 가능한 현재 수동 시험과 미래 API 실행을 구분하지 못한다.

수정 방향: offline_fixture / read_only_research / api_agent의 허용 도구·네트워크·비용을 명시하고 호스트가 모드를 제공한다. 에이전트는 제공되지 않은 도구를 구현했다고 가정하지 않는다.

### P1: 실패 결과의 구조가 불명확하다
정상 연구 객체와 후보 ID조차 없는 실행 오류를 한 형식으로 반환하려다 null 계약 위반이 생겼다. topics=[]만으로는 관련 주제가 없는 것과 실행하지 못한 것을 구별하기 어렵다.

수정 방향: 정상 결과와 execution_error를 분리하고 missing_input, policy_blocked, environment_unavailable, expired_candidate 등의 상태를 정의한다. 빈 주제 목록에도 작업 상태와 제외 이유를 반환한다.

### P1: 근거의 권위와 범위를 더 세분화해야 한다
공식 도메인에도 시민기자 기사·AI 요약·운영기관 공지가 함께 존재한다. 공식 호스트만으로 모든 내용을 동일한 1차 자료로 다루면 안 된다.

수정 방향: publisher_type, evidence_role, event_identity, observed_at를 구분한다. AI 요약·시민기자 체험담은 운영 조건의 유일한 근거로 쓰지 않고 운영기관의 관련 원문을 우선 대조한다.

### P1: 예산 계측의 소유자가 없다
README 기본 60, 저장소 설정 75 등 실제 적용 상한 및 다른 수집기와 공유된 잔여량을 전달하는 수단이 없다. 외부 읽기 도구 내부 HTTP 요청 수도 관측되지 않는다.

수정 방향: 호스트가 effective_budget과 observed_usage를 전달하고 미관측은 null로 둔다. 도구 호출 수와 실제 HTTP 수를 같은 값으로 기록하지 않는다.

## 메인 세션의 독립 원문 대조 — 서브에이전트 성과 아님

1. Npay: 서울시 기사에서 연결된 행사 운영 페이지를 읽으면 포인트·머니 재원, 커넥트 가맹점 조건, 1인 1회 및 한도를 확인할 수 있다. 단순 Npay 결제 전체에 적용하는 요약은 부정확하다. 기간은 10월 23~29일로 표시되어 있으며 연장을 확인하지 않았다.
   - 최초: https://mediahub.seoul.go.kr/archives/2019820
   - 보조: https://mkt.naver.com/event/mo/taste_of_seoul
2. 버스: 최초 문서는 시민기자 기사다. 연결된 서울시 기사에는 시간표·정류소 및 당분간 무료/향후 유료 전환 안내가 있다. 이를 읽어도 오늘의 실제 운행·잔여 좌석·무료 종료일을 보장할 수 없다.
   - 최초: https://mediahub.seoul.go.kr/archives/2019836
   - 보조: https://mediahub.seoul.go.kr/archives/2019790
3. 시민대학: 본문에는 운영기간과 신청 시작일, 과정별 요금이 따로 있다. 운영 종료일까지 신규 신청 가능하다는 결론은 나오지 않는다. 개별 강좌의 현재 접수·잔여석은 별도 확인이 필요하며 이번 메인 대조에서도 확인하지 않았다.
   - https://mediahub.seoul.go.kr/archives/2019003

메인 원문 대조는 후보 내용의 검토 가능성을 확인한 것이다. 기존 승인 조건에 이미 포함된 사실도 많아 새 부가가치를 창출했다고 평가하지 않는다. 최신 실제 이용 가능성을 승인하거나 공개 데이터를 수정하지 않았다.
