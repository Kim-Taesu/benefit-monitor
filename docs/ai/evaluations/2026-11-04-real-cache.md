# 실제 저장 공고 30건: Python 후보와 Codex 추출 비교

## 판단

**기존 Python의 후보 추출을 보완하는 가치는 확인했다. 유료 API 모델의 우위와 비용 효율은 아직 입증하지 못했다.** 실제 문서 30건에서 구체적 조건 60개를 추출했고 모두 저장 원문에 인용이 존재했다. 이것은 합성 시험이 아니다. 다만 신규 공식 자료 탐색·최신성 검증은 아니다.

기존 Python은 상세 조건을 자동 확정하지 않고 검토 후보만 만드는 설계다. 그 빈 조건 필드와 비교한 결과를 ‘정확도 0% → 100%’로 표현하면 부당하다. Python의 근거 없는 주장도 이 비교에서 발견하지 않았다. AI는 기존 검토 작업의 일부를 보조할 수 있는 것이며, Python 자체의 일반적 한계를 증명한 시험이 아니다.

## 실제 수행

- 로컬 `cache/review_texts.json`에 저장된 36개 실제 기사 중 앞 30개를 순서대로 선택. 성과에 따라 고르지 않았다.
- 각 항목의 원래 Python 후보 객체와 저장 본문을 사용했다. baseline 파서를 약화하거나 새로운 단순 정규식 비교군을 만들지 않았다. 과거 후보 재사용이며 현재 코드/최신 웹 재실행은 아니다. 당시 수집 commit은 확정하지 못했다.
- 기존 대화·baseline·승인본을 전달하지 않은 세 Codex 세션이 docs/ai를 읽고 각각 10건에서 중요한 조건 2개씩 추출했다. 모델명을 별도로 지정하지 않았으므로 특정 유료 API 모델 벤치마크가 아니다.
- 메인 세션은 출력 열람 전 원문 10건에 대한 점검 항목을 기록하고, 이후 60개 출력의 인용 실재성과 제안 내용을 검토했다. 독립 인간 정답지 기반 맹검 평가는 아니다.
- 원문 전체는 재게시하지 않는다. 짧은 인용을 포함한 결과와 해시·범위 기록을 첨부했다. 최초 수집 시각과 원문 진본성을 이번 시험에서 재확인하지 못했다.
- 공개 JSON·승인 상태·서비스 화면은 변경하지 않았다. 외부 LLM API·HTTP 요청 0회. 기존 Codex 구독/컴퓨팅 비용은 프로젝트가 보장하지 않는다.

## 발견한 한계와 보완 필요

1. **기존 검토본보다 항상 낫지 않다.** 땡겨요·달빛상품권·손목닥터·다감 등의 핵심 조건은 이미 보강돼 있었다. 실서비스 품질 상승과 기존 수작업 대체 가능성은 구분해야 한다. 검토 시간도 이번에 계측하지 않았다.
2. **부분 추출은 만료 방지에 부족하다.** 미리내집·서영커 등에서 조건은 정확히 뽑았지만 별도 마감일 필드를 요구하지 않아 결과에 종료 상태가 빠졌다. 이는 2개 조건 제한 시험의 한계이며 운영 도입 전 전체 계약으로 다시 평가해야 한다. 기존 검토본의 마감 처리는 유지해야 한다.
3. **공식 도메인이 항상 1차 사업 공고는 아니다.** 임산부 사례는 시민 체험 기사로, 기사 내용에 대한 충실한 추출과 사업기관의 현행 자격 검증은 다르다. 이번에는 기관 원문 추적을 못 했다.
4. **원문 자체의 의문을 찾는 가능성은 보였다.** 청년 이사비의 만 나이/출생일 범위, 다감 본문 ‘생활권자’와 요약 ‘서울시민’, 아리수 ‘구독’/‘팔로우’ 조건 관계를 미확인으로 남겼다. 해당 모순을 해결한 것으로 세지 않는다.
5. **스코프를 더 구조화해야 한다.** 서울식물원 기본 입장료와 특정 전시 적용료를 분리해야 한다. 이번 출력은 미확인 질문을 남겼지만 독립 claim만 카드에 붙이면 잘못 읽힐 수 있다. 장소/프로그램/기간 연결을 승인 전에 확인해야 한다.
6. **범위가 편중돼 있다.** 서울 기사 30건이며 편의점·통신사·첨부 HWP/PDF·실제 정정 탐색은 포함하지 않았다. 최초 30건 도입 평가의 6개 분야 요건을 충족한 것으로 보지 않는다.

## 정확히 무엇이 막혔나

Python 표준 라이브러리 `socket.getaddrinfo(host, 443)`를 실행했다. `mediahub.seoul.go.kr`, `www.seoul.go.kr` 모두 `gaierror: [Errno 8] nodename nor servname provided, or not known`을 반환했다. HTTP 요청 전 이름 해석 단계의 실패다. 사이트 robots 거부, TLS 오류 또는 HTTP 403이라고 진단할 근거는 없다. DNS 설정·실행 환경 네트워크 제한 중 정확한 원인은 확인하지 못했다. 정책 우회와 임의 DNS 변경은 하지 않았다.

따라서 네트워크가 허용되는 실행 환경에서 기존 Python 정책(공식 HTTPS·robots·예산·캐시)을 지켜 1차 공고와 연결 문서를 읽는 조사가 다음 필수 검증이다. 이 실패가 저장 원문 추출 시험까지 막는 것은 아니어서 이번 시험을 수행했다.

## 결제 판단

- **확인됨:** 현재 Python 후보에 빠진 상세 조건을 Codex가 원문 근거와 함께 구조화할 수 있다.
- **아직 미확인:** 새로운 출처를 찾아 필수 누락을 해결하는 능력, 현재 서비스 검토본보다 높은 정확도, 검토 시간 절감, 구매할 API 모델의 동일 성능, 실제 월 비용.
- **현재 결론:** 조사 보조 방식의 시제품을 이어갈 근거는 생겼다. 유료 API 정기 운영 결제를 권할 수준은 아니다. 네트워크 조사와 전체 필수 조건 평가를 먼저 완료하고, 그 결과가 좋을 때만 별도 승인된 제한 예산으로 후보 API 모델을 검증한다.
