# Phase 2 구현 계획 — 브라우저 개인화 연결

## 목표와 범위

공개 AI 주제 카드가 있는 경우에도 로컬 선호와 동의한 반응을 적용한다. 공개 사실·근거·승인 상태는 바꾸지 않고 브라우저에서 후보를 정렬한다. 개인 신청 자격을 추론하거나 프로필을 AI에 보내지 않는다.

이번 구현은 혜택 탭의 추천 경로를 통합한다. 분야별 선호는 현재 근거가 있는 관심 주제(가족 나들이·야간·문화·장보기 할인·편의점 등)를 사용한다. 별도 데이터인 축제·장보기 시세·보건소 탭은 혜택으로 섞지 않는다. 그 탭에 이동 거리·조리 선호를 적용하려면 각 분야의 근거 계약이 추가로 필요하다.

## 작업과 완료 기준

- [x] 공통 순위 함수로 공개 카드와 규칙 카드에 같은 선호·반응을 적용한다. 공개 카드의 근거/만료 검사를 보존한다.
- [x] 명시적 제외를 관심 선택보다 우선하고, 다른 주제에 중복 포함된 같은 항목도 추천에서 제외한다. 제외 이유와 복원 경로를 표시한다. 전체 검색은 유지한다.
- [x] 기존 프로필을 호환해서 읽고 제외 설정을 저장한다. 행동 기록 동의 없이 명시적 설정만 사용할 수 있다.
- [x] 동의한 경우에만 실제 상세 조건을 열어 본 항목의 식별 지문·내용 지문·시각을 보관한다. 처음 보는 정보·다시 보는 정보·내용 변경을 구분하며 갱신 시각만 바뀌면 변경으로 보지 않는다.
- [x] 30일 보관·건수 제한·동의 철회·삭제·저장 실패·다른 탭 동기화를 검증한다.
- [x] 프로필 없음은 공통 추천으로 표시하고, 개인화 이유와 추가 확인 조건을 제공한다.
- [x] 상반된 합성 프로필 3개 이상, 공개 카드 피드백·제외·기간 경과를 단위 테스트와 모바일/데스크톱 E2E로 확인한다.

## 검증과 제품 평가

`npm test`, `npm run typecheck`, `npm run build`, 관련 Playwright E2E, Python 전체 회귀 검사를 실행한다. 원본 작업 트리·유료 실행·공개 JSON은 변경하지 않는다.

Phase 1 사람 유용성 기준선은 아직 없다. 사용자 요청으로 Phase 2 구현을 진행하되 실제 유용성 향상, 상위 5개 추천 평가 20건, 별도 카테고리의 세부 선호까지 완료됐다고 표시하지 않는다.

## 검토 결과

독립 reviewer가 20회 노출만 기록된 경우 주제 순위와 상단 추천의 개인화 판정이 달라지는 문제를 재현했다. `hasPersonalization`으로 판정을 통합하고 노출·철회·만료 회귀 테스트를 추가한 후 독립 재검토를 통과했다.

브라우저 화면에서 추천 이유가 아이콘 열로 배치되는 모바일 오류를 발견해 전체 열을 사용하도록 수정하고 너비 검사를 추가했다. 상세 검증 결과는 [진행 기록](progress.md)에 남긴다.
