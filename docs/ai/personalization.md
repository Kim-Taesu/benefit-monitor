# 혜택 탭의 브라우저 개인화

## 입력과 추천

`beta.ts`의 `topicCandidates`는 표시 가능한 혜택과 공개된 문구에서 후보를 만든다. `published-topics.ts`는 공개 AI 주제의 날짜·근거 스냅샷·현재 표시 후보를 검사한다. 두 경로 모두 `rankTopics`에서 명시적 관심, 제외, 동의한 반응을 적용한다. 기존 기간·철회·공개 검사를 개인화로 우회하지 않는다.

- 직접 선택한 관심 주제는 우선한다. 관심 있어요/없어요는 즉시 순위에 반영한다. 노출·클릭 등 자동 반응은 최근 30일에 노출이 20회 이상인 경우만 반영한다.
- 명시적 제외는 관심 선택보다 우선한다. 제외 주제의 같은 항목이 다른 주제에도 포함되어 있으면 추천에서 함께 제외한다. 공개 의미 분류와 로컬 문구 분류 양쪽 연결을 확인한다. 전체 검색·즐겨찾기의 사실 데이터는 삭제하지 않는다.
- 상단 혜택 추천도 같은 허용 후보와 순서로 재정렬한다. 후보 구성이 바뀌거나 개인화된 경우 공통 AI 요약은 숨겨서 제외된 내용을 언급하거나 개인화를 AI가 수행한 것처럼 보이지 않게 한다. 이미 검증된 개별 문구는 수정하지 않는다. 기존 최소 항목 수 규칙으로 카드 전체가 표시되지 않을 수 있다.
- 지역·통신사·연령은 관련 후보를 찾는 힌트다. 주민 자격·등급·기준일·소득·예외·잔여석을 보장하지 않는다. 참여 비용은 순위의 무료 필터로 사용하지 않는다.
- 프로필 또는 유효한 반응 신호가 없으면 공통 추천임을 표시한다. 프로필이 없어도 동의한 반응이 순위에 사용되면 로컬 개인화라고 표시한다.

## 저장과 동의

기존 `benefit-monitor:beta:v1` 저장 키는 유지하고 내부 레코드만 version 2로 이동한다. version 1을 읽을 때 기존 프로필·동의·유효한 반응을 유지하며 제외·열람 이력은 빈 값으로 시작한다. 잘못된 필드·손상된 값은 기본 상태로 처리한다. `excludedTopics`는 명시적 설정이므로 행동 기록 동의 없이 저장할 수 있다.

행동 동의가 있는 경우에만 상세 조건을 실제로 연 혜택의 식별 지문·내용 지문·열람 시각을 보관한다. URL·제목·원문을 이력에 저장하지 않는다. 지문은 변경 비교용이며 익명화 보장이나 보안 서명이 아니다. 상한은 행동 이벤트 500건, 열람 이력 500건이며 각각 30일이다. 다음 접근·분 단위 갱신 때 지난 자료를 정리한다.

- 처음 확인: 보관 중인 열람 이력이 없다. 서비스에 처음 수집된 시각이나 처음 게시된 뉴스라는 뜻이 아니다.
- 이전에 확인: 상세 조건을 열어 본 내용과 같다.
- 내용 변경: 제목·요약·조건·지역·기간·비용·혜택 수치 등이 바뀌었다. 의미 변화 판정이므로 근거 페이지의 모든 변경을 감지하는 것은 아니다. 확인 시각이나 표시기한 갱신만으로는 변경 표시하지 않는다.
- 동의 없음: 열람 상태를 표시하거나 저장하지 않는다.

동의 철회 시 이벤트와 열람 이력을 함께 비우며 명시적 프로필은 유지한다. 전체 삭제는 프로필도 삭제한다. 저장소 삭제 실패 시 현재 화면의 기록부터 중단하고 사용자에게 실패를 알린다. 다른 탭의 변경은 storage 이벤트로 반영하며, 기록 전에 최신 동의 상태를 다시 확인한다.

## 네트워크와 범위

개인화는 공개 JSON을 읽은 브라우저에서 실행한다. 프로필·반응·열람 이력은 서버·AI·공개 JSON·공유 URL로 전송하지 않는다. 네트워크 E2E에서 공개 페이지의 GET 이외 요청이 없는지 확인한다.

혜택 탭의 분야별 관심은 가족 나들이·야간·문화·야외·할인·편의점 등 현재 주제로 표현한다. 축제·장보기 시세·보건소는 다른 근거 계약의 별도 데이터이며 이번에 혜택 추천으로 섞지 않았다. 이동 거리·조리 선호·보건소 목적별 세부 개인화는 후속 범위다.

합성 프로필에서 다른 순위가 나온다는 사실만으로 유용성 개선을 주장하지 않는다. Phase 1 공통 추천과 비교하는 사람 평가 20건과 개선 폭 결정은 남아 있다.
