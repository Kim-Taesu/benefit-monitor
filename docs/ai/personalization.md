# 혜택 탭의 브라우저 저장 범위

2026-11-15 화면 개편에서 사용자 결정으로 개인화 기능을 없앴다. 나이·통신사·관심 자치구·관심사·제외 주제 설정, 동의 기반 행동 기록, 주제 피드백(관심 있어요/없어요), 반응 통계, "처음 확인·내용 변경" 표시가 대상이다. 2026-11-14 Phase 2에서 만든 추천 순위 개인화도 함께 빠졌다. 되살리려면 Git 이력(`frontend/src/beta.ts`, `published-topics.ts`, `BetaPanel.vue`)에서 가져오고 새 승인을 받는다.

## 지금 브라우저에 저장하는 것

모두 이 브라우저의 `localStorage`에만 두고 서버·AI로 보내지 않는다. 화면 아래 "저장한 것 모두 지우기"로 한 번에 지운다.

| 키 | 내용 | 코드 |
|---|---|---|
| `benefit-monitor:favorites:v1` | 즐겨찾기한 혜택의 출처·공식 URL(최대 200개) | `favorites.ts` |
| `benefit-monitor:interests:v1` | 내 지역(서울 자치구 하나 또는 빈 값). 고르면 바로 저장한다 | `preferences.ts` |
| `benefit-monitor:visit:v1` | 이번·지난 방문 시각, 그때 보인 혜택의 지문(16자리, 원문·URL 없음, 최대 500개), 소개 문구를 닫았는지 | `visit.ts` |

- 예전 키 `benefit-monitor:beta:v1`(프로필·행동 기록)은 화면을 열 때 지운다.
- 내 지역을 고르면 그 구의 안내와, 특정 구에 묶이지 않은 서울·전국 공통 안내를 함께 보인다(`topics.ts` `matchesHome`). 주소의 `region` 값이 저장값보다 먼저다.
- "새로 올라옴"은 지난 방문 때 보이지 않던 항목에만 붙는다. 6시간 안의 재방문은 같은 방문으로 본다. 공개 데이터에 처음 공개된 시각이 없고 확인 시각은 재확인 때마다 바뀌므로 시각만으로는 가릴 수 없어 지문을 함께 둔다. 유효한 목록을 받지 못한 방문은 기록하지 않는다.

## 주제

주제 칩은 공개 승인된 주제 카드(`topic_cards`)가 있으면 그것만 쓰고, 없거나 기한이 지나면 제목 단어 규칙(`topics.ts` `ruleTopics`)으로 묶는다. 순서는 혜택이 많은 주제부터이며 비용 상태로 정하지 않는다. 혜택 2건 미만인 주제는 "주제 더보기" 뒤에 접는다. 기존 기간·철회·공개 검사는 그대로다.
