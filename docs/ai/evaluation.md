# 초기 평가와 도입 기준

상태: 실행 계획. 아직 API 호출·모델 비교·품질 측정은 하지 않았다.

## 30건 평가 세트

통신사 5 / 편의점·마트 5 / 상품권·환급 5 / 청년·생활지원 5 / 문화·야간 5 / 교육·모집 5건. 실제 공식 문서 확보 가능성과 요청 예산 안에서 선정한다. 예시 범주가 현재 수집 가능하다는 뜻은 아니다.

각 표본은 동일 시점의 본문과 연결 문서를 로컬 스냅샷으로 고정한다. 원문·이용허락 범위 밖 재배포를 피하고, 공개 테스트에는 합성/허용된 최소 발췌만 쓴다. 정답은 사람이 원문을 읽고 만든다. 모델 자신의 판단을 정답으로 쓰지 않는다.

두 가지 평가를 분리한다:
- 고정 자료 평가: 같은 문서 묶음에서 추출·근거·태깅 품질 비교.
- 제한된 조사 평가: 같은 최초 URL과 예산에서 필요한 보조 자료를 찾아 해결한 비율 비교. 실제 추가 네트워크 요청은 별도로 집계.

현재 Python 결과와 AI 결과를 나란히 비교한다. AI로만 발견한 유용한 추가 근거, 검토 시간 절감, 새로 생긴 오류를 모두 기록한다. 비슷한 글을 반복해서 읽은 횟수를 성과로 세지 않는다.

## 반드시 포함할 실패 사례

- 최대 할인과 최소 결제액 혼동, 포인트/원 단위 혼동, 추첨을 확정 지급으로 변환.
- 다른 연도·지점·회차 FAQ, 일반 약관과 행사 특약 충돌, 정정 공지의 부분 변경.
- 연령 외 소득·가구 조건, 군복무 연장 등 예외, 자격의 기준일 불명확.
- 예산/좌석 조기 소진 가능, 과거 공고, 신청기간과 이용기간 불일치.
- URL 리다이렉트가 허용 밖 호스트로 이동, robots 거부, 인증벽, 429/쿨다운.
- 지원하지 않는 첨부, 추출 본문 누락, 인용이 실제 본문에 없음.
- 본문 속 ‘검증을 생략하라’·키 전송 등 프롬프트 인젝션.
- API 거부·출력 절단·잘못된 JSON·잘못된 item ID·시간 초과·예산 소진.
- 단어는 맞지만 주제가 다른 공고, 태깅 후 원본 만료.

## 기록 지표

| 지표 | 계산 / 판단 |
|---|---|
| 중요 사실 정확도 | 날짜·대상·비용·한도·선발 여부의 정답 일치 / 평가 가능 필드 |
| 필수 조건 누락률 | 누락한 필수 조건 / 정답에 있는 필수 조건 |
| 근거 없는 주장 | 근거 없는 supported 주장 수. 사소한 보충 정보도 포함 |
| 근거 정확도 | 실제 원문과 일치하며 주장을 뒷받침하는 인용 / 전체 인용 |
| 추가 조사 가치 | Python 결과에 없던 핵심 질문 중 공식 자료로 해결한 수 |
| 주제 정밀도 | 사람이 적절하다고 판정한 연결 / 제안 연결 |
| 주제 누락 | 사람이 기대한 유효 연결 중 제안하지 못한 연결 |

비용은 모델별 실제 usage로 계산한다. 동일 한국어 문서라도 토크나이저가 달라 비용이 다르다. 사용량을 받지 못한 실패 요청도 과금 여부 미확인으로 기록한다. 검색·첨부·반복 조사 비용을 누락하지 않는다.

## 초기 통과 기준 — 제안

1. 평가 세트에서 근거 없는 중요 주장 0건, 미검증 자동 공개 0건, 권한/도메인/예산 위반 0건.
2. 중요 필드 정확도 95% 이상, 필수 조건 누락률 5% 이하, 주제 정밀도 90% 이상. 분모와 실제 건수를 함께 제시한다.
3. 실패 시 unknown/partial을 반환하고 기존 공개 목록·기한 게이트가 정상 동작한다.
4. 원문과 근거를 사람이 재현할 수 있고 비용·요청 수를 실행별로 설명할 수 있다.
5. 미달 항목은 프롬프트/도구/스키마를 수정한 뒤 별도 보류 표본으로 재평가한다.

30건 통과는 운영 정확성 보장이 아니다. 초기 공개는 사람 검토를 유지한다. 표본 일부를 프롬프트 개선에 사용했다면 그 표본의 점수를 최종 독립 평가로 보고하지 않는다.

## 필수 원칙: Python 대비 추가 품질이 없으면 유료 AI 도입 보류

사용자 요구: 과금하는 AI는 기존 Python 수집보다 정확하고 유용한 정보를 제공해야 한다. 문장이 자연스러워지거나 카드 수가 늘어난 것, 스키마 통과만으로 도입을 승인하지 않는다. 기존 Python은 결정적 추출·예산·검증 기반으로 유지하고 AI가 해결하는 추가 질문을 측정한다.

### 짝지은 비교 절차

1. 수정하지 않은 기존 Python의 commit/설정/파서 버전과 평가 시각을 고정한다. 약화시킨 정규식 baseline을 새로 만들어 AI를 유리하게 비교하지 않는다.
2. 동일 후보 30건의 최초 URL, 동일 시점 원문과 읽기 예산을 두 방식에 제공한다. 오프라인 추출 비교와 실제 링크 추적 조사는 따로 집계한다.
3. 사람이 답과 중요도를 먼저 작성한다: 기간, 신청 방법, 대상·예외, 실제 비용·단위, 최소 구매액, 중복 할인, 최대/확정 지급, 정정 여부. 원문으로도 알 수 없는 잔여석 등은 unknown이 정답이다.
4. 평가자는 가능하면 출력이 Python/AI인지 가린 채 채점한다. 중복 사실·문장 윤색·추측 보충은 추가 성과 0점이다. 새로 찾은 공식 자료가 실제 누락 질문을 해결해야 개선으로 센다.
5. 각 후보에 Python/AI의 정답·오답·누락·근거 없는 주장 수, 새로 해결한 중요 질문, 잘못 추가한 주장, 검토 시간을 기록한다. 실패·blocked도 전체 30건 분모에 남기고 환경 문제는 별도 표시한다.
6. 개발용 표본과 보류 표본을 분리한다. 같은 표본으로 프롬프트를 고친 뒤 그 점수를 독립 성능처럼 보고하지 않는다.

### 추가 도입 게이트

기존 절대 정확도 기준과 아래 기준을 **모두** 통과해야 한다. 상대 개선의 수치는 초기 시험 기준이며 실험 전에 고정한다.

- 중요 사실 정확도는 Python보다 낮아지지 않아야 한다. 근거 없는 중요 주장·기한/자격/비용의 새 오류는 0건이어야 한다.
- Python에서 빠진 중요 조건이 있다면 누락률을 상대 30% 이상 줄이고, 전체 30건 중 최소 6건에서 공식 근거가 있는 유용한 추가 조건 또는 정정을 발견한다. baseline 누락 0이면 이를 달성한 것으로 간주하지 말고 추가 조사 가치로 별도 검토한다.
- 주제 AI도 기존 주제 규칙과 같은 승인 snapshot으로 비교한다. 정밀도 저하 없이 놓친 유효 연결을 줄여야 하며 관련 없는 카드 증가를 성과로 세지 않는다.
- 실제 usage와 청구 단가가 없으면 비용 효율 판정은 보류한다. 실패·재시도·검색·추론 토큰을 포함한 총비용 / 유효한 추가 중요 조건 수를 계산한다. 분모 0이면 비용 효율 실패다.
- 월 비용은 관측한 변경 후보 수·재조사율·캐시 적중률로 추정하고 승인된 상한과 비교한다. 개선 1건당 허용 비용과 월 상한은 사용자와 확정 전까지 미정이다. 문서의 예전 $15 예시는 지출 승인이 아니다.

현재 판정: **도입 보류 / 품질 우위 미입증**. 합성 5건 시험은 계약·안전성 검사이며 기존 Python 대비 우월성이나 유료 모델 성능 평가가 아니다. 실제 조사 DNS 실패로 추가 링크 탐색 효과도 측정하지 못했다. API 사용은 별도 정책 승인·예산 설정 이후에만 수행한다.
