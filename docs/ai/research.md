# 작업 지침 01 — 공식 혜택 조사

버전: research-v1. [공통 규칙](README.md)을 먼저 적용한다.

## 입력

후보 ID, source ID, 공식 URL, 기존 후보 필드, 이전 근거 해시·조회 시각, 변경 이유, 현재 KST 기준 시각, 허용 출처와 남은 요청/토큰 예산을 받는다. 사용자의 개인 정보는 받지 않는다.

## 조사 절차

1. **대상을 고정한다.** 운영 기관, 행사 이름, 연도·차수·지점·대상 지역을 식별한다. 식별이 불명확하면 다른 공고와 합치지 않는다.
2. **원문을 읽는다.** 제목만 아니라 본문·주의사항을 확인하고 본문 해시/조회 시각/추출 범위를 기록한다. 행사 링크가 목록이면 실제 상세 페이지를 찾는다.
3. **빠진 질문을 만든다.** 아래 항목에서 혜택 판단에 영향을 주는 미확인 사항을 3개 이내로 우선순위화한다.
4. **필요한 공식 자료를 추가로 읽는다.** 연결된 공고문·유의사항·주최 기관 FAQ·해당 행사의 정정/종료 공지를 순서대로 확인한다. 관계없는 배경 설명은 수집하지 않는다.
5. **조건을 대조한다.** 같은 행사에 적용되는 자료인지 확인하고 주장별 원문 근거를 연결한다. 상충하는 내용은 양쪽을 기록한다.
6. **추가 탐색 여부를 결정한다.** 필수 질문 해결, 반복 결과, 한도 도달, 접근 불가, 자료 불일치 중 하나면 종료한다. 검증되지 않은 공백을 채우려고 탐색을 무한 반복하지 않는다.
7. **초안을 작성한다.** 확인된 주장·미확인 질문·충돌·후속 검토 요청을 [출력 계약](output-contract.md)에 맞춰 반환한다. 후속 Claude 실험의 모델 응답은 [표준 추출 v3](research-extraction.md)를 사용하며 Python 조립 후 기존 계약을 검증한다.

각 추가 문서 요청 전 `확인할 질문 / 이 URL이 관련된 이유 / 해결되면 중단할 조건`을 짧게 기록한다. 모델의 내부 사고 과정이나 장황한 추론 로그는 저장하지 않는다.

## 필수 확인 항목

| 구분 | 확인할 내용 |
|---|---|
| 혜택 | 할인/지원/환급/적립/체험의 종류, 정확한 값과 최대값, 추첨/선발 여부 |
| 날짜 | 공고일, 신청 시작·마감, 실제 이용 기간, 회차별 시간, 기준 시간대 |
| 대상 | 지역·연령 범위·연령 기준일·통신사 등급·회원 조건·소득 등 복합 조건 |
| 비용 | 무료/유료/혼합/미확인, 참가비·최소 결제·보증금·추가 비용 |
| 이용 조건 | 결제 재원·제외 수단·쿠폰 발급·사전 예약·중복 할인·횟수/금액 한도 |
| 이용 방법 | 공식 신청 링크·절차·장소·준비물 중 명시된 것 |
| 현재 상태 | 원문이 명시한 접수 종료·정정·취소와 그 기준 시각 |

원문에 없는 요일, 출생연도, 누적 절약액 등을 모델이 계산하지 않는다. 필요 시 별도의 결정적 계산 결과로 구분하고 산식과 입력 근거를 붙여 검토한다. 자격 충족 판단은 제공하지 않는다.

## 출처 충돌 처리

- 행사에 명시적으로 적용되는 공식 정정 공지는 원 공고와의 관계와 변경 범위를 확인한 뒤 우선 제안할 수 있다.
- 게시일이 새롭다는 이유만으로 다른 연도/회차/지점 공고를 우선하지 않는다.
- 공식 상세 공고와 해당 첨부·유의사항을 우선 비교한다. 일반 FAQ는 해당 행사 적용 여부가 확인되어야 한다.
- 충돌이 해소되지 않으면 disputed와 양쪽 근거를 유지하고, 중요한 날짜·비용·대상 충돌은 공개 후보 변환을 차단한다.
- 비공식 글은 공식 원문을 찾는 단서일 뿐 사실 근거로 사용하지 않는다. 현재 도구 정책이 비공식 탐색을 금지하면 열지 않는다.

## 사례 — 모두 작업 설명용, 실제 혜택 아님

- KT 할인: ‘최대 할인’만 추출하지 말고 등급·적용일·포인트 차감·최소 결제·중복 제외를 유의사항에서 찾는다. 잔여 포인트나 개인별 적용 가능 여부는 모른다.
- 청년 교육: 연령 범위가 맞아도 1인가구·거주지·전 회차 참석·선발 조건을 별도 필드로 보존한다.
- 상품권: 구매 할인, 사용 시 환급, 특정 결제 재원, 지급일·한도를 구분한다. 독립된 두 할인율을 합산하지 않는다.
- 야간 행사: 야간 운영 사실과 날짜가 근거에 있어야 한다. 사진이 어둡거나 행사명이 ‘달빛’이라는 이유만으로 야간 행사라고 확정하지 않는다.
- 첨부만 존재: 지원하지 않는 파일을 읽었다고 주장하지 말고 unreadable_attachment로 검토 요청한다.

## 완료 기준

근거 없는 새 사실 0개, 모든 확인 주장에 원문 인용·URL·조회 시각·해시 연결, 핵심 미확인 사항의 명시, 조사 중단 사유 기록. 완료는 조사 작업의 종료이며 공개 승인이나 서울 전수 조사 완료가 아니다.
