# 작업 지침 02 — 의미 태깅과 주제 구성

버전: topics-v1. [공통 규칙](README.md)과 [출력 계약](output-contract.md)을 적용한다.

## 목적과 입력

검증된 혜택을 생활 맥락별로 연결한다. 입력은 현재 표시 가능한 검증 항목 ID, 승인된 필드·근거, 목록 버전, 주제 사전이다. 조사 대기/만료/미검증 항목을 입력에서 제외한다. 개인 프로필과 행동 기록을 모델에 전달하지 않는다.

## 절차

1. 각 항목의 실제 이용 행동과 조건을 읽는다. 단어 하나가 있다는 이유로 분류하지 않는다.
2. 아래 기존 주제에 연결하고 그 이유와 근거 claim ID를 남긴다.
3. 관련 없는 항목과 제외 이유를 기록한다. 적절한 주제가 없으면 연결을 강제하지 않는다.
4. 충분히 구별되는 항목 묶음이 있을 때만 신규 주제 후보를 제안한다. 초기 제안 기준은 서로 다른 항목 2개 이상이며 운영자가 변경 가능한 편집 기준이다.
5. 같은 항목의 복수 주제 연결은 허용한다. 전체 건수는 주제별 건수 합산으로 계산하지 않는다.
6. 게시 전 기존 ID/근거/유효기한을 코드로 재검사하고 신규 주제·표현은 사람이 검토한다.

## 기존 주제 사전

| ID | 포함 근거 | 잘못된 연결 예 |
|---|---|---|
| local | 실제 혜택 적용 지역/주민 조건 | 주최 기관 주소만 해당 구인 경우 |
| carrier | 명시된 통신사/멤버십 조건 | 본문에 다른 통신사 비교가 잠깐 등장 |
| age | 명시된 연령 범위와 관련 조건 | ‘청년’ 단어만으로 20세 확정 |
| night | 명시된 야간 운영·해당 시간대 | ‘달빛’ 이름만으로 판단 |
| culture | 전시·공연·문화 참여 자체 | 공고 게시 기관이 문화재단인 경우 |
| learning | 교육·강좌·학습 참여 | 강사 채용을 수강 혜택으로 연결 |
| shopping | 구매 할인·적립·환급 | 모든 유료 행사를 쇼핑으로 분류 |
| vouchers | 상품권 발행·구매·사용 혜택 | 결제수단 제외 항목에 상품권 언급 |
| convenience | 편의점에서 실제 적용되는 혜택 | 무관한 행사 장소 주변 편의점 안내 |
| outdoors | 걷기·러닝·공원 등 실제 야외 활동 | 실내 행사 오시는 길에 공원 언급 |
| family | 가족·어린이 참여 프로그램 | 자격 제외 조건에 자녀 언급 |
| housing | 주거 지원·입주·임대·분양 모집 | 일자리 공고의 주택 보유 제외 조건 |
| career | 채용·취업·면접 지원 | 교육 전반을 취업 확정 혜택으로 표현 |

## 개인화와 자격의 분리

AI는 주제와 조건 메타데이터를 만든다. 브라우저가 사용자가 명시적으로 설정한 지역·통신사·연령·관심사와 연결한다. 나이와 통신사가 일치해도 소득·가구·등급·기준일 조건까지 충족했다고 표현하지 않는다.

‘내 KT 멤버십 활용하기’, ‘은평구에서 누릴 혜택’ 같은 제목은 설정값을 템플릿에 넣는다. 사용자 개인 정보가 AI에 갈 필요가 없다. 서울 전체와 개별 구, 전국 적용과 특정 구 주민 조건을 구분한다.

화면은 이모지 + 제목 + 코드가 계산한 유효 건수만 표시한다. 클릭하면 기존 혜택 목록을 필터링하고, 카드 클릭으로 상세 근거/조건 모달을 연다. 클릭 때 API를 호출하지 않는다.

## 유지와 실패 처리

항목 만료/검증 철회 시 주제 연결도 즉시 제거한다. 연결된 항목이 없으면 주제를 숨긴다. 태그 출력 실패·버전 불일치·검증 불합격이면 마지막 결과의 유효 ID를 재검사하거나 기존 beta.ts 규칙으로 복귀한다. 오래된 주제 캐시로 만료 항목을 부활시키지 않는다.

매일 수집한 공식 자료에 따른 주제 카드 교체·순위 갱신은 사용자가 지정한 목표 범위에 포함한다. 클릭·검색 등 사용자 행동을 이용한 자동 학습은 별도이며 이번 입력에 포함하지 않는다.

## 매일 자료를 판단해 카드 갱신 — 사용자 요구 반영

목표 실행 단위는 하루다. 공식 자료 검색·조건 보강과 같은 실행에서 기존 카드와 비교하고 유지·추가·교체·제거·순서 변경을 판단한다. 변경할 근거가 없으면 유지할 수 있다. 아래는 소액 실험에 포함할 목표 동작이며 현재 운영 스케줄·일괄 게시·변경 이력 스키마가 구현됐다는 뜻은 아니다.

1. 호스트가 KST 기준 시각, 오늘 수집 성공/실패/캐시 상태, 새 공고·본문 변경·정정·만료 신호와 기존 카드를 준비한다. 공고 본문이 같아도 마감까지 남은 기간·이용일 변화는 판단 입력에 포함한다.
2. AI가 검색 결과를 읽고 추가 공식 자료를 요청해 조건·충돌·미확인을 정리한다. 호스트가 모든 HTTP·robots·캐시·쿨다운·예산을 통제한다.
3. 기존 공개 게이트를 통과한 유효 항목·근거만 카드 구성 입력에 전달한다. 새 조사 초안이 자동으로 검증 사실이 되는 것은 아니다. 변경된 중요 사실은 기존 승인·재검증 경계를 따른다.
4. AI가 오늘의 생활 주제를 선택하고 제목·설명·포함 항목·표시 순서를 결정한다. 마감 임박, 주말 일정, 새 혜택, 적용 조건 변화를 고려하며 카드마다 기존 대비 변경 이유와 근거 ID를 남긴다. 서로 다른 프로그램의 비용·자격·할인을 합산하지 않는다.
5. 호스트가 참조 ID·근거·유효기한·중복·금지 표현과 표시 조건을 다시 검사한 뒤 카드 묶음을 한 번에 갱신한다. 코드가 건수를 계산하며, 실제 개인 자격·재고·신청 성공을 AI가 보장하지 않는다.
6. 조회 실패를 혜택 종료로 판단하지 않는다. API/검증/예산 실패 시 이전 카드에서 만료·철회 항목을 제거한 유효 부분이나 기존 규칙 결과를 사용한다. 같은 자료·시각·버전의 중복 실행은 추가 변경을 만들지 않도록 한다.

운영 목표는 검증된 항목 안에서 AI가 매일 카드 편집을 자동 결정하는 것이다. 기존 사실 승인과 매일의 카드 편집은 구분한다. 카드마다 매일 사람 승인을 요구하는 동작을 목표로 하지 않는다. 현재 v1의 신규 주제/표현 사람 검토 경계는 소액 실험에서 의미 정확도·유효성·실패 복귀를 검증한 뒤 운영 구현 시 명시적으로 변경한다.

소액 실험에서는 여러 날의 새 공고·마감·정정·수집 실패를 연속 스냅샷으로 재생해 카드 변경 결과를 비교한다. 검색·조건 보강·주제 판단의 호출과 비용을 합쳐 승인된 일회 상한 안에서 측정한다. 반복적인 일일 과금·스케줄 활성화·실제 공개 반영은 아직 실행하지 않는다.

## 2026-11-05 일별 재생 판정

Claude CLI와 유효 항목 스냅샷·실패 fallback은 구현했다. 날짜별 3회 재생에서 ID·근거·만료 검사는 통과했지만 청년 교류의 career 오분류와 가족·주말 제목 오류가 발생했다. 의미 검토 미통과로 자동 공개·정기 실행은 보류한다. [실험 결과](evaluations/claude-pilot-2026-11-05/README.md).

## 호스트 편집 근거와 의미 검사

후속 Claude 주제 요청은 항목별 `topic_basis`를 요구한다. 호스트가 허용 주제·제목 조건·기존 claim 참조를 작성하고 모델이 이를 승인하거나 덮어쓰지 않는다. 누락·다른 항목 claim·근거 없는 연결은 거절한다. 가족·주말·무료 제목은 포함 항목 전체가 해당 조건을 가져야 한다. 상대 날짜 표현과 인식하지 못한 자유 제목은 사람 검토로 남긴다. 모델 reason에 관련성이 적혀 있다는 사실만으로 통과시키지 않는다.

실패 fallback도 같은 편집 근거를 확인하고 일반 제목으로 바꾼다. 주제 자체가 잘못된 연결은 제거한다. 이 검사는 명시된 편집 입력을 대조하는 제한된 규칙이며 범용 자연어 진실 판별이나 사람의 의미 검토를 대체하지 않는다. [추가 과금 없는 재검증](evaluations/claude-quality-2026-11-05/README.md)에서 기존 출력 3회 모두 검토 대기를 유지했다.

## 승인된4일 운영의 편집 경계

사용자 승인 범위에서 기존 공개 승인·현재 유효 사실만 주제 입력으로 전달한다. 문화·체험·교육·강좌·할인·적립의3개 검토 분류 정책과 호스트가 제공한 topic_basis, allowed_topic_titles를 따른다. 허용 목록 밖 ID나 제목·카드 전체 자격 조건은 공개하지 않는다. 원래 사실·확인 시각·요금·결제조건은 호스트가 대조하며 AI가 바꾸지 않는다. 첫 실제 주제 제안은 검사에서 거절됐고 실제 공개 화면은 기존 규칙으로 복귀했다. [현재 운영 상태](automation.md).
