# Phase 3 — 필요한 조건을 보충하는 제한된 조사

## 구현 범위

첫 사용 사례는 공식 나들이/문화 안내의 이용 기간·대상·비용·신청 방법 확인이다. 개인 프로필은 전송하지 않는다. 기존 `research` 호출 안에서 미확인 필드와 발견된 공식 링크 ID를 지정하며, 호스트가 한 문서를 읽고 전체 근거를 다시 추출한다. 새 검색 공급자·모델·유료 호출 종류는 만들지 않는다.

기존 일일 실행에는 기본값이 켜진 `investigate_missing_conditions` 정책을 연결한다. 켜면 해당 후보는 최대 3회 모델 호출·총 4문서로 제한하고, 모든 호출은 기존 하루 조사 한도와 월 원장을 사용한다. 추가 문서가 없거나 변하지 않은 입력은 재호출하지 않는다. 거절·공급자 오류·충돌은 즉시 종료한다. 기존 기본 수집/조사 경로는 그대로 둔다.

## 완료 기준

- [x] 출력은 사실 추출과 별도의 read/stop 요청으로 나누며 링크 ID·누락 필드를 코드가 검사한다.
- [x] 읽은 공식 문서에서 발견한 링크만 허용하고 새로운 도메인은 비공개 후보로만 기록한다.
- [x] robots/TLS/기존 HTTP 예산/캐시/실패 대기를 유지하며 조사 내 HTTP 상한도 검사한다.
- [x] 단계·근거·누락 조건·종료 사유를 저장한다. 충분한 근거가 아니면 자동 공개하지 않는다.
- [x] 재실행은 이전에 추가한 문서도 다시 확인하고, 변경 없는 입력을 재결제하지 않는다.
- [x] 10개 이상 합성 조사 사례와 실제 기존 게이트/원장/호출 수 회귀 검사를 통과한다.
- [x] 기존 프롬프트/서명 경로의 영향과 신규 확장 스키마를 검증한다.

운영 활성화·배포와 현재 모델의 추가 정보 발견 효과는 별도 관측이다. 구현 테스트 결과로 사용자 재검색 감소를 주장하지 않는다.

구현·로컬 검증 상세는 [추가 조사 계약](investigation.md)을 따른다. 공급자 확장 스키마 시험·현재 모델 실행·운영 활성화는 수행하지 않았다. 공식 읽기 smoke는 URLError로 실패했다. 따라서 Phase 3의 운영 효과까지 달성한 것으로 표시하지 않는다.
