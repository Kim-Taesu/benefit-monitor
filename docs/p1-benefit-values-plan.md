# P1: 공식 근거가 있는 혜택 수치

목표: 사람이 공식 원문으로 확인한 할인/지원/환급/포인트 수치를 조건과 함께 보존하고 표시한다.
기존 public/verified.json의 실제 항목은 수정하지 않는다. 제목·조건에서 숫자를 추출하거나 재검증 시각을 갱신하지 않는다.
예상 절약액 계산·개인 자격 확정·통화 변환은 P2이며 수행하지 않는다.

선택적 benefit_value 객체: kind(discount_amount, discount_rate, grant_amount, refund_amount, reward_points),
value, qualifier(exact/up_to), conditions, evidence_url, evidence_quote. 빈 객체/필드 누락은 기존 동작 유지.
금액은 양의 원화 정수(최대 999,999,999,999), 포인트는 양의 정수, 할인율은 0 초과 100 이하 소수 둘째 자리까지.
참여 비용·최소 지출·결제 한도는 기존 fee_status/conditions/payment_terms와 구분한다.

근거는 해당 출처의 허용 HTTPS URL이어야 하며 이미 본문 변경을 관찰하는 URL(payment_terms.evidence_url 또는 item.url)과
같아야 한다. 복수 원문 감시 범위를 늘리거나 요청 예산을 늘리지 않는다. 원문 인용은 내부 evidence에 포함된 공개 가능한
문구여야 하고 사람이 사실·수치·단위·최대 여부·조건을 확인해야 한다. 인용은 입력값의 아라비아 숫자·원/%/포인트·혜택 종류·최대 표시가 연결된 단일 구절 전체와 일치해야 한다. 결제 조건 문장 또는 부호가 있는 수치를 양의 혜택으로 재해석하지 않는다. 5천원/만원 등 축약 표현은 자동 환산하지 않고 필드를 생략한다. 구조 검사는 사실 검증을 대신하지 않는다.
새 객체는 기존 승인/보고서 비교·재검증·만료 게이트를 통과해야 공개된다. 빈 객체는 내용 해시와 공개 출력에서 생략해 호환성을 유지한다.

Python 스키마/검증/승인 일치/개인정보/Markdown/legacy HTML, Node 어댑터의 유효·무효·기한 검사,
브라우저 조건/근거/잘못된 수치 노출 금지 및 기존 접근성 회귀를 검증하고 별도 PR로 제시한다.
